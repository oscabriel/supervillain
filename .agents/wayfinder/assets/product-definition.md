# supervillain — product definition

_The destination artifact of the wayfinder map (ticket 016). Every claim traces to a closed ticket resolution or a linked asset; where the map leaves fog, this document names it rather than filling it. This is the spine — the detailed assets are the muscles, linked at each seam._

## What supervillain is

supervillain is a terminal-first virtual tabletop. Players `ssh` into a live game room and sit at a real table rendered in their terminal; the GM hosts that table from their own machine. It launches with Draw Steel on a system-agnostic base, and it is built so the game you run is a folder of plain files you own and the key you connect with is the only account you need. Free to self-host, forever.

## Surfaces

Three surfaces, terminal-first ([001](../tickets/001-product-surfaces.md)):

1. **SSH terminal tabletop** — players `ssh <room>@supervillain.app` into rooms; the proven core, rendered with OpenTUI.
2. **`supervillain` CLI** — the GM's tool: mint and host rooms, manage campaigns and characters, publish artifacts.
3. **Web surface (supervillain.app + a backend)** — marketing, docs, and read-only artifact pages at launch; a paid in-browser terminal into the _same_ sessions later.

Explicitly **not** a surface: a parallel web VTT client. The future browser terminal is a thin client into the existing session infrastructure, not a second renderer — see [browser-terminal-bridge](browser-terminal-bridge.md).

## Pillars

Named, load-bearing, and marketing-page material:

- **"Your key is your account."** Identity is an ed25519 public key everywhere — an SSH key fingerprint for players, an iroh NodeId for GM/CLI, a passkey for the future browser. No signup ([009](../tickets/009-identity-across-surfaces.md)). _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): NodeId is gone with iroh, and the pillar survives verbatim — its real content (no signup; presenting a key is logging in; an unknown key becomes an identity on first contact) never depended on it. Identity is the **equivalence class of linked keys** (ADR-0005); the backend's internal per-class id is plumbing and never user-facing — a user-facing handle would be a definition patch. The lost half is key-as-**address**: reaching a table now goes through a gateway registry, and copy must never imply the cryptographic-reachability meaning. The GM's hosting machine authenticates with a per-machine key linked through the ordinary ADR-0005 flow — no new identity primitive; key revocation graduates to required.)_
- **"You own your campaign."** A campaign is a folder of plain, hand-editable files on the GM's disk — a JSONL event log plus sidecar character files. No opaque database; portability is moving the folder ([010](../tickets/010-cli-artifact-scope.md)). _(Correction 2026-07-21, [Agents at the campaign folder #46](https://github.com/oscabriel/supervillain/issues/46): a stated property of this pillar — **plain files are an agent surface by construction**. Point any coding agent at the campaign folder and it can draft NPCs into sidecar files, summarize a session from the JSONL log, or author maps — zero product work, because there is no API between the GM and their data. A differentiator no centralized VTT can copy, since their data lives behind their API. The invariants agents get: (1) agents edit files under exactly the GM's hand-edit contract — same files, same between-sessions timing, same validators (`content` schemas for characters, the core validator for maps); the file _is_ the API, and there will never be a separate agent API. (2) The log is read-only to everything but the host — agents may read the JSONL freely, but appending is the host's single-writer authority (ADR-0001 restated at the file surface); any future agent-at-the-table goes through the command path like every client. (3) Agent edits cannot corrupt history, structurally — replay never reads files, and bad sidecar edits are caught by validators at load time; rendering tiers (ADR-0007) never touch file formats. Explicitly not promised: format freeze — formats stay plain text and documented, but schemas may evolve; validators are the compatibility contract, not byte layouts.)_
- **GM-hosted is the center of gravity.** "A game necessarily has a GM." Room authority lives on the GM's machine by default; gateway-hosted rooms are a supported second mode, not the core ([007](../tickets/007-hosting-authority-model.md)).
- **Free core, forever.** Self-hosting costs us nothing, so GM-hosted play, the CLI, and joining rooms via the gateway are free forever ([011](../tickets/011-business-shape.md)). _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): the rationale is retired — under the outbound hybrid the company carries render+broker cost for every remote table, so "costs us nothing" is false. The promise stands with its honest new footing: the hosted gateway is free **deliberately, as the funnel** toward the v3 paid tier, behind protective caps whose numbers wait for the R9 benchmark; self-hosting stays free because the gateway binary is MIT in the open repo.)_

## System-agnostic base + the game module seam

The core is game-neutral: rooms, seats, presence, chat, generic dice, the shared event log, feed, and layout. Each game's content, schemas, and flows live in a **per-game module**. Draw Steel is the first module; Mothership and Mörk Borg are the expected expansion ([002](../tickets/002-game-system-scope.md)).

A game module is **code** — a TypeScript package behind a small core-defined interface, statically imported and compile-time registered. No rules DSL, no plugin framework, no dynamic loading. Four entry points, one package ([006](../tickets/006-game-module-seam.md), full spec: [game-module-seam](game-module-seam.md)):

| entry point | provides | consumer edge |
| --- | --- | --- |
| `model` | `S`/`C`/`E` types, `init`, `apply` — pure, platform-free | everyone |
| `authority` | `decide` — all randomness, all authority | **host** (model+authority) |
| `view` | panels, `renderEvent` | **gateway/table** (model+view) |
| `content` | packaged data, terminology, file validators | **CLI** (model+content); also read by `authority` and `view` |

Key invariants (the rest are in the asset):

- **Host never imports OpenTUI; the render side never imports `decide`.** Those two prohibitions are the seam, and they are mechanically enforced (below).
- **One shared JSONL log.** `core.*` events (rooms, seats, presence, chat, generic dice) and `ds.*` events interleave; game state is an **opaque serializable subtree** the core persists but never inspects.
- **Replay never reads files.** `init()` is deterministic; all randomness happens in `decide` and lands in the event payload; content-derived facts (derived stat blocks) land in payloads too. A GM can edit content mid-campaign and old events replay byte-identical. **Room logs are portable and self-contained.** _(Correction 2026-07-21, [Fold posture #47](https://github.com/oscabriel/supervillain/issues/47), [ADR-0010](../../adr/0010-fold-posture-writers-halt-readers-tolerate.md): host-side validation at append time was never the whole story — render-side folds refold logs that skew, bugs, or crafted stores can make partially uninterpretable, and the definition left their posture open. Pinned: every fold classifies events as **unknown** (unrecognized type) or **known-invalid** (recognized type, violated shape/invariant), and the posture keys on holding the pen — **writers halt, readers tolerate**. The host refuses to open a log on either tier (unknown types are a version fence protecting the canonical log); render folds never halt — unknown skips silently for forward compat, known-invalid skips loudly as a warning FeedLine with seq/type/reason (seq = JSONL line number), burst-collapsed during replay. And the replay promise gains its evolution clause: **shipped shapes fold forever** — any shape a released host wrote stays valid in every future fold via upgrade-on-read; no log migrations, no type-name reuse; the promise attaches at first public release.)_
- **`TableView`** is a read-only snapshot value passed to `decide` — the licensed churn point where v1 growth is honest. The **envelope is the core's forever-promise**; payload versioning is the module's problem.
- **The fake game module** is the second adapter, spanning all four entry points — the core's conformance fixture, present from v0, so core tests cross the same seam Draw Steel does.

## Hosting & authority model

Both modes, one codebase, GM-hosted as the center of gravity ([007](../tickets/007-hosting-authority-model.md)):

- **GM-hosted (the flagship, and v0):** room authority runs on the GM's machine via `supervillain create` (the create command _is_ the host); the campaign JSONL lives on the GM's disk; players reach it over iroh. The gateway is a doorway, not a landlord. The CLI verb set used throughout the resolutions is `create` / `join` / `publish`. _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): players reach it **through the gateway** — the Host **dials out** to the gateway over one authenticated WebSocket/TLS pipe (all rooms and channels multiplexed; auto-reconnects forever; submits never auto-retry, ADR-0001 unchanged) and remote players never connect to the GM's machine directly. iroh is dropped from launch scope. Everything else in this bullet stands: authority, files, and the create-is-the-host meaning are untouched — only reachability centralizes. `create` works with no gateway and no account (local table); a configured gateway adds dial-out + registration.)_ _(Correction 2026-07-25, [#65](https://github.com/oscabriel/supervillain/issues/65), [ADR-0014](../../adr/0014-one-binary-two-roles-gateway-role-selector-and-homelab-state.md): "the CLI verb set" is the **table** surface and stays pinned at exactly those three — it was never the CLI's whole surface. The management side already grew nouns outside it (`key`, `character`, `map`, `campaign`), and the self-hosted gateway ADR-0012 promises now joins them as a **role selector**, not a fourth verb: `supervillain gateway serve` runs the gateway role out of the same compiled binary. No re-pinning, no new player-facing verb; the two roles stay apart behind one deferred import that the lattice enforces.)_
- **Gateway-hosted (supported, arrives v3):** rooms that persist while the GM sleeps, running on our servers. This is the paid tier — built last so it debuts as pure addition, never a paywalling of something free.
- **The RoomStore seam** — one interface, in-process store or iroh client behind it — is a standing architectural commitment that keeps both modes on one reducer and one codebase, and keeps a late pivot to gateway-first available as a fallback. _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): the seam survives with the client behind it renamed — in-process store or **broker client over `transport-ws`**. `room-wire` becomes transport-neutral (mechanically enforced: it may import no transport package), so a future iroh return is another adapter behind the same interface, trigger-gated on measured demand for direct/serverless play.)_

**What supervillain.app durably stores:** gateway-hosted room logs (once that mode exists) and the name→NodeId registry for GM-hosted rooms. Nothing durable for GM-hosted tables themselves — those live on the GM's disk. _(Correction 2026-07-22, [#44](https://github.com/oscabriel/supervillain/issues/44), [ADR-0008](../../adr/0008-bare-ssh-lobby-lazy-guest-minting-and-keyed-preference-persistence.md): plus a presentation-preferences table at v1 — resolved identity → render/theme toggles for keyed users, never game or campaign state; guests stay session-local. "Stateless gateway" is re-pinned to mean no game state.)_ _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): the registry becomes **name→owner identity** (durable, survives disconnects) plus **name→live pipe** (memory-only routing). And ADR-0008's re-pin is sharpened to no **durable** game state: the gateway may hold game-derived state in memory only — the per-Room fold it renders from, reconnect snapshots, session buffers — never on disk or in the DB; a restart loses only live sessions. Game content never enters logs, metrics, telemetry, or crash reports (the never-log list lives in ADR-0012); transit privacy is a stated **policy**, never marketed as E2E — the property is available by self-hosting.)_ _(Correction 2026-07-25, [ADR-0013](../../adr/0013-server-data-layer-gateway-owned-identity-and-two-stores.md): the durable list is attributed per store. **Gateway:** name→owner identity, presentation prefs, the key-equivalence graph, revoked keys, link codes (plus the ed25519 host key as a file). **Backend:** published artifacts, capability tokens, dead-token tombstones. The gateway also holds the graph in the **self-hosted** posture, where no backend exists at all — that is why identity lives there.)_

## Identity across surfaces

Key-as-account, everywhere ([009](../tickets/009-identity-across-surfaces.md)):

- **Terminal:** SSH key fingerprint for players, iroh NodeId for GM/CLI _(correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): NodeId is gone — the GM/CLI side authenticates with a per-machine ed25519 key linked into the same equivalence graph via the ADR-0005 code flow; ed25519 stays the unifying primitive)_. A keyless **guest path** exists with a can't-miss upgrade box; guest progress is **adopted** on upgrade by appending a linking event, so historical attribution stays immutable while progress becomes reachable (prototype-validated — [prototype-lessons](prototype-lessons.md)). _(Correction 2026-07-20, [Key linking and guest adoption flow #34](https://github.com/oscabriel/supervillain/issues/34): the upgrade box shows a single-use adoption code (7-day expiry), minted at guest session start; redeeming it from the CLI performs the adoption. Bringing a key without the CLI still works — continuity going forward, adoption deferred until linked.)_
- **Cross-device key linking is launch-tier (v1):** one-time codes bind a second key to the same identity. The first GM with a desktop and a laptop hits this immediately. GM roaming (joining your own room from any machine) falls out of linking + key-as- account; the room host stays where it was minted. _(Correction 2026-07-20, [#34](https://github.com/oscabriel/supervillain/issues/34), [ADR-0005](../../adr/0005-key-linking-backend-registry-gateway-conduit-and-in-log-linking-events.md): mechanized — linking is terminal-only and CLI-only via a `key` noun (`supervillain key link [code]`, #28's noun pattern; room verbs untouched); device codes 15 min, adoption codes 7 days, both single-use; the backend holds the key-equivalence graph, rooms materialize it as gateway-stamped `core.actor-linked` log events delivered over the registration connection, so folds stay log-deterministic and roaming needs no mechanism of its own.)_
- **Web read-only artifacts: capability URLs.** The unguessable share link _is_ the permission; revocable by the owner from terminal/CLI. **No web accounts** at launch.
- **Browser terminal (v3): passkey against the web backend.** A passkey is a keypair, so "your key is your account" survives the browser; the gateway mints the browser session onto the same identity primitive. Ed25519 public keys are the unifying primitive across SSH keys, NodeIds, and passkeys.

## CLI scope

The `supervillain` CLI is the GM's tool ([010](../tickets/010-cli-artifact-scope.md)):

- **Launch nouns: campaigns and characters.** Maps are deferred — they drag in the battle-map (FrameBuffer) story, its own scope tier. _(Correction 2026-07-18, [v1 launch plan map #29](https://github.com/oscabriel/supervillain/issues/29): battle maps moved into v1, so maps join the launch noun set; the map-artifact shape is specified on the map's battle-map ticket [#39](https://github.com/oscabriel/supervillain/issues/39).)_ _(Correction 2026-07-21, [#39](https://github.com/oscabriel/supervillain/issues/39): the shape is pinned — a map is a plain-text file in `maps/`: a metadata header (name, legend) then an ASCII grid body, one character per cell, legend-mapped to a core-pinned tile vocabulary (floor, wall, difficult, hazard, door) with a NetHack-informed default legend (`.` floor, `#` wall, `+` door, `^` hazard, `~` difficult); terrain-only (tokens are live-play state in the log), hard size bound ~200×100 cells; core owns the format and validator, GMs author instances in their editor.)_
- **A campaign is a folder of plain files** on the GM's disk: a JSONL event log plus human-readable sidecar character files a GM can hand-edit between sessions. No opaque database.
- **Portability is "move the folder."** `export`/sync verbs are vN polish.
- **`supervillain publish <artifact>`** mints the read-only capability URL — the bridge that makes the web surface real.
- **Offline:** characters are editable offline; rooms are mintable/resumable but only playable with a live host.

## Business shape

([011](../tickets/011-business-shape.md))

- **The core is free forever** — GM-hosted play, the CLI, joining rooms via the gateway. Self-hosting costs us nothing. _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): still free forever, honest new footing — see the pillar correction. Hosted-gateway free tier ships with protective caps (rooms per identity, sessions per room, idle timeouts, output budgets); cap numbers and any capacity claim wait for the R9 benchmark; at capacity the lobby refuses new sessions honestly, live tables are never degraded. **Self-hosting is now a designed surface, not a side effect** — three postures, all first-class: hosted (default, zero setup), self-hosted gateway (the same MIT compiled binary on a VPS or homelab box — one forwarded port + DDNS, the exposed protocol is SSH; an always-on home box can run the Host too, which dissolves the sleeping-laptop gap for that cohort), and local/offline (no gateway). Data ownership holds in all three; connectivity ownership arrives with postures 2–3. LAN play is the self-hosted posture at distance zero — a docs recipe, no mechanism. Self-hosted TLS: self-signed cert, fingerprint pinned via the Host-onboarding pairing code; no CA, domain, or reverse proxy ever required.)_ _(Scope stated 2026-07-25, [ADR-0013](../../adr/0013-server-data-layer-gateway-owned-identity-and-two-stores.md): the self-hosted posture is the **gateway** — play, the door, the broker. **Publishing and the web surface are hosted-only at v1**, and this must be said plainly in the docs rather than left as fog. The reason is not our code: **browsers do not do trust-on-first-use**, so a capability URL served from a homelab box on a self-signed cert warns every recipient — self-hosted publishing needs a real domain and a CA certificate, exactly what this posture promises never to require. Deferred, not forbidden: because the key graph is gateway-local, a future web role co-located with a self-hosted gateway reads the same store in the same process, so posture 2b is a dependency to add, never a data migration.)_ _(Correction 2026-07-25, [#65](https://github.com/oscabriel/supervillain/issues/65), [ADR-0014](../../adr/0014-one-binary-two-roles-gateway-role-selector-and-homelab-state.md): "the same MIT compiled binary" is now true of the artifact users download — `supervillain gateway serve` runs the gateway role out of the one released binary, and a release smoke exercises that role on a clean box before any release ships. A self-hosted gateway keeps its state in `${XDG_STATE_HOME:-~/.local/state}/supervillain/gateway` — never the campaign folder; [#40](https://github.com/oscabriel/supervillain/issues/40)'s `/var/lib/supervillain/` stays the operated box's path, reached only by an explicit `--state`, since nothing infers a posture from the machine.)_
- **The paid story is one bundle: "host your game on our servers"** — persistence (rooms up while the GM sleeps) + browser access (the in-browser terminal is a paid perk, not a free surface) + **maybe AI features** (explicitly a MAYBE). _(Correction 2026-07-21, [#46](https://github.com/oscabriel/supervillain/issues/46): the AI MAYBE is bounded by **who runs the compute** — it means features **we operate**: our compute, our models, gateway-side conveniences. A user's own agent reading and writing their own files is not a feature of ours to sell; it is a property of plain files, free by construction, forever. The paid MAYBE must never be read as paywalling the campaign folder — anything at the file-system level is user-owned and user-operated.)_
- **Licensed content: one-time charges, down the line**, contingent on actual agreements with game makers.
- **Nothing payment-shaped at launch.** The scaffold must only avoid painting the web backend into a corner payments can't be added to. Checkout venue (web vs terminal) is left open; default expectation is web.

## Brand voice

Restraint. Structural copy — menus, help bars, errors — stays dry, legible, and serious, because this is an actual play tool; the deadpan-villainy register surfaces only at the emotional beats (a room minted → "your table is live. summon your players:", the guest-upgrade box, empty states, marketing headlines) and is never explained. Full-commitment theming (GM as "mastermind" everywhere) is rejected because it fights the seriousness of the tool. The name is locked as **supervillain**; the canonical domain is **supervillain.app**, and in-product copy reads `ssh <room>@supervillain.app` ([012](../tickets/012-naming-branding.md)). _(Correction 2026-07-22, [Short CLI command #52](https://github.com/oscabriel/supervillain/issues/52): the short CLI command is **`vil`** — a sibling `bin` alias installed next to the canonical `supervillain` binary; `vil --help`/`--version` identify as supervillain. `sv` is rejected outright: hard PATH collisions (svelte CLI, runit) and overwhelming svelte mindshare with our audience. Docs and copy keep `supervillain <verb>` as canonical — `vil` is convenience, not branding; `lair` as a fiction alias was considered and set aside per this section's restraint.)_

## Web launch scope

Launch web = **marketing + docs + artifact pages** (character sheets, session logs) as capability URLs — minimal but present, because they are the product's shareable loop ([013](../tickets/013-web-launch-scope.md)). _(Correction 2026-07-21, [#39](https://github.com/oscabriel/supervillain/issues/39): battle maps are the third artifact type — `supervillain publish map <name>` snapshots the map file's content (name + legend + grid, terrain only, no play state) under the same re-publish/revoke contract; the page is a static monospace grid render of the core-owned format — zero game imports — and its OG card is a terminal-styled mini-render of the map.)_

- **Publish = snapshot push.** `supervillain publish` copies the artifact's data to the web backend at publish time, so URLs work while the GM's laptop sleeps. Re-publish to update, revoke to delete. Publishing is a visible act of copying data _out of_ your folder — reinforcing "you own your campaign."
- **Capability URLs ship custom OpenGraph images** — per-artifact OG cards, because the link unfurl in a group chat is the page's first impression. Implies server-side OG image generation at launch.
- **One backend service** owns the registry API, key-link codes, and capability-URL mint/revoke/render + OG generation. The SSH gateway stays its own process: two deployables, one monorepo.
- **No user auth at launch.** Capability URLs are the access model; passkeys arrive with the paid tier. The backend profile is: a DB, public HTTP, server-rendered pages, OG images — passkey-ready but with an empty auth slot.

_(Correction 2026-07-21, [#33](https://github.com/oscabriel/supervillain/issues/33), [ADR-0009](../../adr/0009-capability-url-and-publish-contract.md): the full publish contract is pinned. A capability URL is **stable per artifact** — keyed by (owner identity, type, name); re-publish updates in place, revoke kills the URL forever, a post-revoke publish mints fresh. The log's publishable unit is the **room log** (`publish log <room>`; no session-boundary concept — session structure is date-derived UTC fragment anchors; per-slice publish and query-param filtered views are named churn). CLI surface: `publish <type> <name>` / `publish revoke <type> <name>` / `publish list`, with the backend as the sole truth for publish state — no local receipts. Ownership resolves through the key-linking graph (any linked key manages the identity's artifacts; linking never breaks URLs). The payload is a **self-describing snapshot document** — core-owned, integer-versioned, built by the CLI from its statically-imported game packages — so the **web imports zero game code** for artifact pages, settling the "possibly no game import at all" hope affirmatively. Log pages render inline `core.map-loaded` events as a collapsed `map-grid` block shared with map pages (terrain-only, tokens never overlaid); web map grids render as real text in a self-hosted MonoMek webfont — the ADR-0007 glyph atlas stays terminal-side (lattice-legal on the web edge but unmotivated). OG cards render a core-owned game-blind `card` section of the document; OG image URLs derive from the capability token and die with it (cached chat unfurls are honestly non-recallable). Retention: no expiry — live until revoked; a per-artifact size cap enforced at publish (initial 10 MB, ops-tunable); the backend renders every document version it ever accepted, launch ships version 1, version retirement is deliberately fog.)_

## Scope tiers

Exactly as ticket [014](../tickets/014-scope-tiers.md) resolved them:

| tier | headline | what it adds |
| --- | --- | --- |
| **v0** | a real Draw Steel table plays over SSH | GM-first room over iroh; both player doors; neutral core + thin DS module; persistent campaign folder; iroh CI gate is the first build milestone |
| **v1** | flagship story complete — **this is launch** | DS at play-support depth; campaigns + characters as CLI nouns; `publish`; web launch (marketing/docs/artifact pages + OG); cross-device key linking + guest adoption; **still GM-hosted only** |
| **v2** | character builder | the retention move; its own licensing pass (a builder reproduces far more rulebook content than a renderer) |
| **v3** | the paid tier | gateway-hosted rooms + browser terminal + payments debut **together**; timed on demand signal |
| **v4+** | second game | Mothership / Mörk Borg, only once Draw Steel is deep |
| **vN** | unordered roadmap | battle maps, AI features, expansion-playbook detail |

**v0 detail** (the milestone-1 seed):

- **GM-first**, not gateway-first. Rationale: matches the center of gravity, and gateway persistence _is_ the paid tier — building it first would build the paid feature before the free core. The iroh CI-matrix gate is the first milestone; the fallback ladder (Node room host → Rust sidecar) bounds the risk to schedule, not existence. _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): GM-first stands; the gate and the ladder die with iroh. Milestone 1's gate is now the **broker suite** — see the Milestone 1 correction — and the fallback ladder is deleted: a plain outbound WebSocket needs no Rust sidecar insurance.)_
- **Two player doors, one client:** `ssh supervillain.app` is mandatory (zero-install is the pitch; the gateway is a stateless doorway — name registry + iroh proxy), and direct `supervillain join` over iroh also ships. Both are the same RoomStore-client seam. _(Correction 2026-07-22, [#44](https://github.com/oscabriel/supervillain/issues/44), [ADR-0008](../../adr/0008-bare-ssh-lobby-lazy-guest-minting-and-keyed-preference-persistence.md): bare `ssh supervillain.app` — no room name — lands in a live **lobby** TUI on the gateway (splash with the ADR-0007 pixel-glyph wordmark, interactive join, become-a-GM install pitch, settings); unknown and offline room names land in the same chrome with distinct honest notices. Guests are pre-identity in the lobby — the ADR-0003 `guest:` actor mints lazily at first room entry, upgrade box at that threshold. Lobby chrome ships at v0 with the gateway; the keyed-preferences store and the launch copy pass land at v1 with #37. The gateway still never creates rooms; a local launcher TUI for GM-side interactivity is a separate surfaced ticket.)_ _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): the direct-iroh second door is gone. `ssh <room>@supervillain.app` is **the** player door; `supervillain join` survives as a thin front door over it — an ordinary SSH session using the CLI-managed key against the configured gateway, no parallel client protocol at launch. The CLI is tooling, never a membership card: at launch `join` adds convenience, not capability, over bare SSH. A native local-render join mode is named future work, triggered by measured gateway render cost or latency. The lobby, guest minting, and upgrade box are unchanged.)_
- **Gameplay floor:** neutral core (chat, dice, shared log, presence) + a thin Draw Steel module — power rolls with edges/banes, a DS-shaped initiative tracker, read-only stat blocks loaded from files. Proves the 006 seam with one real module. Draw Steel independence notice in-product from day one.
- **Persistent:** rooms append JSONL to the campaign folder and resume after GM restart. No artifacts, publish, web, or key linking in v0; identity is key-as-account automatically.
- **Seats are log-derived** _(correction 2026-07-14, surfaced by issue #8 — the definition said the core owns seats but never specified claiming)_: room creation claims the GM seat (`gm`) for the creating key; a joining key claims a seat on arrival (`core.seat-claimed`, seats named `player-N` in claim order); a key holds at most one seat per room, so reconnecting with the same key returns to the same seat, and claiming is idempotent. Seat events replay like everything else — a joiner's fold derives the same seating the host holds. Guest identity is the SSH door's concern (#9); the direct door always has a key. Before the gateway registry exists, the direct door's room-ref is the iroh ticket `create` prints — names arrive with #9. _(Correction 2026-07-14, issue #9, [ADR-0003](../../adr/0003-gateway-registration-trusted-stamping-and-guest-actors.md): names arrive via `create --name <room> [--gateway <addr>]`, which registers name→host-address at the gateway over iroh; ownership is the registering key, re-registration by the same key updates the address. The receipt's gateway identity becomes the host's sole trusted stamper, letting the gateway submit for the players it proxies without weakening ADR-0001. Keyless SSH lands as a per-session `guest:<12 hex>` actor via keyboard-interactive, behind the upgrade box.)_
- **Solo play is a named supported mode — by construction** _(correction 2026-07-21, [#45](https://github.com/oscabriel/supervillain/issues/45))_: one human runs `supervillain create`, attaches over the local TTY (a day-one session adapter), holds the GM seat, and runs the whole table through existing GM superset authority — any character's play commands, all tokens, maps, dice, chat — no gateway, no iroh, fully offline. The seat rule stands unchanged: a key holds at most one seat per room; no multi-seat bend, no multiple-keys workaround blessed. The mode ships **no solo affordances** (see the Solo affordances fog entry), and the DS v1 floor gets zero solo items — DS is a poor solo flagship. Marketing: **"one person can run the whole table solo" is a launch pitch line**, capability-worded, never a solo-experience/oracle promise; "offline" is a supporting fact under the your-machine/your-files hosting story, not a pitch line.

**v1 depth:** DS at **play-support depth only** — full sheet rendering, condition tracking, resource tracking (heroic resources, recoveries, surges), victory tallies. Character files are still authored outside the app. **No builder** (biggest scope trap, and the licensing-heaviest surface — held to v2). _(Correction 2026-07-18, [v1 launch plan map #29](https://github.com/oscabriel/supervillain/issues/29): **battle maps move from the vN roadmap into v1** — the FrameBuffer story, map artifacts, and their sharing model, which the definition held must arrive together, arrive here. Scope is pinned by tickets [#38](https://github.com/oscabriel/supervillain/issues/38) and [#39](https://github.com/oscabriel/supervillain/issues/39); the vN row keeps its original text as history.)_ _(Correction 2026-07-21, [#39](https://github.com/oscabriel/supervillain/issues/39), [ADR-0006](../../adr/0006-core-owned-battle-maps-and-inline-map-capture.md): v1 battle maps = terrain grid + movable tokens, **core-owned** — `core.map-*`/`core.token-*` events, a core chrome map region, zero game-module seam growth. GM load command → the host reads and validates the map file and appends `core.map-loaded` with legend + grid fully inline, so replay stays file-free. Token = id + glyph + label + position + optional seat binding, no game fields; the GM does everything, a player moves only their own seat-bound token; keyboard-first, mouse click as enhancement, no drag promise. Rendering stays inside the exact-ANSI-16 theme-token contract in one FrameBufferRenderable, one map cell per terminal cell. Fog of war, in-app editor, and image import are cut to named churn.)_ _(Correction 2026-07-21, [#49](https://github.com/oscabriel/supervillain/issues/49), [ADR-0007](../../adr/0007-pixel-glyph-rendering-tier.md): the map surface gains a **pixel-glyph rendering tier** as the default — MonoMek (CC0) glyphs baked at build time into a 1-bit atlas and rasterized as Unicode quadrant blocks, one map tile = 4×4 terminal cells in a scrolling viewport; ornamental chrome set-pieces may use it, body text never. Still exact-ANSI-16 (the palette churn row is not fired), zero event/seam/format change; v1 target, slippable by construction.)_ _(Correction 2026-07-21, [#46](https://github.com/oscabriel/supervillain/issues/46): v1 adds one deliberate agent artifact — an **AGENTS.md-style template file scaffolded into the campaign folder** with the campaign CLI noun, documenting the folder layout, file formats, and the hard rules (edit sidecar files between sessions; never write the log) in the place agents look. ## Monorepo shape & stack

**The better-t-stack verdict: there is no invocation.** bts is wrong for this product; the workspace is hand-rolled ([015](../tickets/015-monorepo-stack.md), full spec: [monorepo-stack](monorepo-stack.md)). Verified against a fresh clone (e1bf536f): `bts add` is addon-only and `bts.jsonc`-gated with no path into a foreign workspace; bts has no library-package generator and no dependency-cruiser; its opentui addon is a local single-process TUI starter, dismissed explicitly. bts survives only as a convention reference and a possible v1 `apps/web` graft source.

**Workspace tree:**

```
apps/
  gateway/           # SSH session adapter, name registry, iroh proxy
  cli/               # supervillain: host embedding, campaign nouns, local attach
packages/
  config/            # strict tsconfig base, dependency-cruiser rules, shared tool config
  core/              # envelope, log, registries (interfaces), seam interfaces,
                     # TableView, theme-token types
  table/             # the shared client: renderer fold, core chrome (feed, layout
                     # slots, focus routing, rejection feedback), token→ANSI resolution
  room-host/         # single-writer host: decide loop, JSONL persistence,
                     # in-process RoomStore adapter
  room-wire/         # RoomStore wire protocol over the transport seam: codec,
                     # serve half, iroh client adapter (correction — ADR-0001)
  transport-iroh/    # iroh endpoint behind the narrow transport seam
  session/           # transport-neutral session contract
  identity/          # ed25519 key-as-account primitives (SSH key ↔ NodeId)
  games/draw-steel/  # model / authority / view / content
  games/fake/        # conformance fixture, all four entry points
```

_(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): the tree above is history at three nodes. `packages/transport-iroh` is deleted; its lattice slot is **`packages/transport-ws`** — a thin WebSocket adapter, client half (Host dial-out) and server half (gateway-only import). `packages/room-wire`'s comment becomes "RoomStore wire protocol + the broker frame protocol (room/channel tags, chunking, registration choreography) over one abstract connection interface — transport-neutral, imports no transport package." `apps/gateway`'s comment becomes "SSH session adapter, name registry, broker server (per-Room fold, per-session views)." )_

Structural calls: **`packages/table` is the shared client** — the only OpenTUI consumer outside game `view` entries; it serves both v0 doors and v3's browser terminal, and never imports `decide`. **`room-host` is a package, not an app** — three consumers (CLI in-process at v0, gateway in-process at v3, Node-fallback bin if it lands that way). **Registries compose in the apps** (apps do the static game imports; room-host takes an injected authority registry and stays game-agnostic). **`session` is real on day one** — the gateway's SSH adapter and the CLI's local-TTY attach are two genuine adapters of one contract, never typed to ssh2. **No `apps/web` until v1.**

**Tooling:**

- **Plain Bun workspaces, no Turborepo** (root scripts + `tsc -b` cover this size).
- **TypeScript 7** (native tsc, GA 2026-07-08); every package `composite: true` off the `packages/config` strict base; **all packages emit js + d.ts** (no bundler; apps consume built output). The Node-compat set compiles under `nodenext` so emitted output is Node-loadable by construction — the hedge's first enforcer.
- **oxlint + oxfmt** (pinned; oxfmt is 0.x — absorb format churn deliberately).
- **dependency-cruiser rules in `packages/config`, CI from day one** — the lattice enforcement: `games/*` imported only by apps; `@opentui/*` only in `packages/table` and `games/*/view`; nothing on the table side imports `decide`; `content` imports `model` only; `bun:*`/`@opentui/*` banned across the Node-compat set; only `apps/gateway` imports `bun:sqlite`. _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): two rules change — **`room-wire` may import no transport package** (the transport-neutral seam, mechanized), and only `apps/gateway` imports `transport-ws`'s server half; the render side imports neither half.)_
- **Test discipline — the runner is the runtime claim.** Bun-bound code → `bun test`; the Node-compat set → vitest under Node. **`transport-iroh` + `room-host` run the same specs under both runners — that dual lane IS the 008 CI matrix.** _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): the dual lane survives iroh's death with a new rationale — the event-sourced core stays runtime-portable; only the edges (Table, gateway render, CLI binary) are Bun-bound. The both-runners set is now **`room-host` + `room-wire` + `transport-ws`**.)_

**The CLI artifact:** a **compiled Bun binary** (`bun build --compile`) — "host your table from one file you downloaded." It statically imports the game packages, so DS's packaged content rides inside the binary and a GM's binary version pins their content version. Platforms: **linux-x64, linux-arm64, macos-arm64 (three triples)** — macos-x64 was dropped from the original four-triple set when the hello-iroh smoke surfaced that upstream publishes no darwin-x64 iroh artifact (its ADR was deleted with iroh — see [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md)); Windows GMs via WSL2 (named churn, revisit trigger: a real Windows GM cohort). Built per-triple on native CI runners; curl installer + checksums + macOS codesign from day one; GitHub releases at v0 (brew/npm deferred). **Distribution invariant:** one file → one archive (binary + sidecar `.node`) → **never "install a runtime."** The Node fallback rung is a dev/CI hedge and the gateway's option, not a GM-shippable artifact. _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): **macos-x64 returns** — its sole blocker (no darwin-x64 iroh artifact) is dead; four triples again, conditional on a passing darwin-x64 CI smoke build before any public platform claim. The sidecar `.node` disappears with the napi artifact: OpenTUI's Zig lib (solved upstream via `$bunfs`) is the binary's only remaining native piece, so the archive shape simplifies toward truly one file.)_ _(Correction 2026-07-25, [#65](https://github.com/oscabriel/supervillain/issues/65), [ADR-0014](../../adr/0014-one-binary-two-roles-gateway-role-selector-and-homelab-state.md): the artifact is no longer only "the CLI" — it is **one binary, two roles**. The same compiled file runs the table roles (`create`/`join` and the management nouns) and the **gateway role** (`supervillain gateway serve`), which is what makes ADR-0012's "same single compiled binary" self-hosting promise true of a download. One artifact per triple still, one archive, one checksum row; a second named artifact was rejected. The release smoke now covers both roles.)_

**The data edge:** the **event log is the canonical durable data — plain files** (campaign folder now; gateway room logs via the RoomStore seam at v3). Server-side databases are only ever lookup/index state, so ORM pressure never develops. The gateway store is **SQLite via `bun:sqlite`, directly — no ORM**; v0 schema is the name→NodeId registry (~one table), with a ten-line `PRAGMA user_version` migration helper from day one. _(Correction 2026-07-24, [ADR-0012](../../adr/0012-outbound-only-hybrid-drop-iroh-host-dials-out.md): the v0 schema is the **name→owner-identity** registry — durable ownership only; name→live-pipe routing is process memory, and nothing game-derived ever lands in this database.)_ _(Correction 2026-07-25, [ADR-0013](../../adr/0013-server-data-layer-gateway-owned-identity-and-two-stores.md): there are **two stores**, both SQLite, and the split is per deployable. **Gateway store** (`bun:sqlite`, raw prepared statements, no ORM — unchanged): name→owner identity, presentation prefs, the **key-equivalence graph** (relocated from the backend, so identity resolution and revocation are local reads that work with no backend in existence), revoked keys, link codes. **Backend store** (SQLite too, with **Drizzle** as a typed query layer — the churn row is cashed): published artifacts, capability tokens, dead-token tombstones; snapshot documents are files on disk under `/var/lib/supervillain/` with rows pointing at them, never blobs. The backend reads identity through a narrow interface with local and remote implementations, so the hop lands on the cold publish path and never on authentication. **One migration mechanism** governs both — the existing `PRAGMA user_version` runner; drizzle-kit is not adopted, and a startup assertion keeps the Drizzle schema from drifting off the SQL. The standing constraint is unbent: server DBs stay lookup/index state and ORM pressure must not develop — Drizzle is licensed as a query layer, not as an ORM. Because the boundary is the deployable, **the binary users download never carries Drizzle**.)_
