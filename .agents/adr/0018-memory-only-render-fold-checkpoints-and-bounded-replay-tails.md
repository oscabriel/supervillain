# Memory-only render-fold checkpoints and bounded replay tails

Issue #77 exposes two forms of the same unbounded work in the gateway's per-Room fold: it retains every Envelope for the life of an attachment, and every arriving Table applies that complete history again. The 2026-07-25 R9 run measured **15.3 s of gateway CPU to seat 100 players (153 ms per arrival)** and identified per-arrival replay as part of that growth. A focused 2026-07-26 probe on the same R9 box measured the current pure table fold at 0.13 ms median for 1,000 small chat Envelopes and 0.39 ms for 10,000, while a `RoomFold` retaining 100,000 of those Envelopes added about 10 MiB RSS; the absolute micro-times exclude OpenTUI redraw and SSH setup, but both probes establish the linear variable. The current implementation has no ceiling: a Room attached for months retains and replays its entire Log even after every view closes.

**Decision: a live Room carries one memory-only render-fold checkpoint plus a bounded contiguous tail, produced inside its `RoomFold`.** `room-wire` owns checkpoint sequence, compaction, the tail, and atomic replay capture. It remains game- and table-blind: the gateway composition root injects a producer made by `packages/table` from the Room's registered `ViewEntry`; the producer's checkpoint payload is opaque to `room-wire`. This is the deliberate `packages/table` contract change the glossary's fold correction required. A joining Table accepts an optional checkpoint, restores its render fold from it, then applies the retained tail and the live stream through the ordinary `apply` path. Local and older `RoomStore` adapters remain replay-only; checkpoint replay is an optional acceleration on the store interface, not a second authority path.

**The checkpoint contains the state a Table otherwise derives by replay:** the module's serializable state, seats and character bindings, actor-link equivalence classes, map and tokens, the known-invalid replay-warning accumulator, and the most recent rendered FeedLines needed to reproduce the initial visible feed. It carries an integer payload version and `throughSeq`; it contains no Envelope and no command authority. The session actor is deliberately absent: it is overlaid by the joining Table, so one checkpoint serves every view. The snapshot producer uses the same `createTableFold` implementation as a session — there is no second reducer to drift.

**Exact-replay equivalence is the acceptance invariant (ADR-0010).** For one Log, (a) a fresh Table fold over every Envelope and (b) a Table restored from the checkpoint and folded over the tail must finish with structurally identical game state, TableView apart from the joining actor overlay, actor equivalence, map, tokens, skip summary, and visible FeedLines. The test compares both paths over the same mixed core/game Log, including linking, map/token changes, a known-invalid event, and events on both sides of the compaction point. Unknown events and known-invalid events retain ADR-0010's reader posture because checkpoint production calls the same render fold: unknown skips silently; known-invalid skips loudly and contributes to the same collapsed replay warning.

The Feed needs an explicit bound because retaining an unbounded transcript in the checkpoint would merely rename the memory leak. The production PTY ceiling is 100 rows (R9), so the checkpoint retains the latest **100 non-null FeedLines** from the compacted prefix; the raw tail contributes its own later lines. This reproduces the bytes initially visible after a full replay at every admitted PTY height while deliberately bounding a late joiner's older scrollback. A Table that was already open keeps the lines it personally saw. Historical scrollback is not canonical state — the Log on the Host is — and fetching arbitrary old feed pages is not introduced here. If product use shows late joiners need searchable full-room transcript, that is a separate on-demand Host projection, not permission to restore unbounded gateway RAM.

**Compaction keeps the latest 512 Envelopes.** When a 513th Envelope arrives, `RoomFold` applies the oldest retained Envelope to the checkpoint producer, advances the checkpoint through that sequence, and evicts that one Envelope. It never applies the retained tail to the checkpoint, so join cannot double-apply it. Snapshot payload cloning happens only when a join captures the artifact, not on every append. The number deliberately matches the R9-gated per-session lag budget and is five times the 100-row PTY ceiling; it bounds one Room's replay work while leaving ample contiguous context for renderer output and diagnostics. The dated benchmark note records 106.5 ms late-join CPU at 1,000 Envelopes and 124.7 ms at 10,000 (+17.0%), while the old 10,000-Envelope path failed to complete in 60 s. Reopen 512 if either 10,000-Envelope join CPU exceeds the 1,000-Envelope result by more than **20%** on the R9 harness, or ordinary-play telemetry/diagnosis needs more than 512 raw Envelopes to explain a rendered failure. A cap change requires a new dated benchmark note.

**Memory-only remains absolute (ADR-0012 NQ-11 / ADR-0013).** Checkpoint payload, tail, cursors, and session copies exist only in gateway RAM. They are never written to SQLite, files, logs, metrics, telemetry, or crash exhaust. They disappear when the Room detaches, its pipe dies, the same identity supersedes the attachment, the fold closes, or the gateway restarts. The existing NQ-11 test is widened so distinctive content present only in a checkpoint is absent from the registry and exhaust after compaction.

**The Host remains the source of truth.** A checkpoint is derived, disposable, and grants no authority. A fresh attachment always rebuilds it by replaying from Envelope 1 over the Host pipe. Detach, same-identity supersession, fold close, a missing game entry, a checkpoint payload-version mismatch, a non-contiguous sequence, or a producer failure invalidates it. Producer/sequence failure ends that derived fold rather than serving suspect state; replacement attachment rebuilds from the Host. A checkpoint-version mismatch is impossible between producer and consumer in one gateway binary, but the Table rejects it rather than interpreting skewed state.

**Admission and isolation do not change.** `reserveView(capacity)` remains synchronous and one-shot. The per-Room checkpoint starts folding at attachment, independently of every arrival; a refused arrival causes no additional info request, producer work, snapshot clone, stream read, submit-channel open, view, or fold mutation. A successful reservation is still counted only when opened. Before capture, replay waits for the first 25 ms quiet gap in the upstream stream (which has no backlog marker). Capture then freezes the bounded tail for that view and atomically registers its live cursor after it, so shared compaction cannot remove the view's initial tail while it consumes it; the existing per-view lag budget still drops only that view for live lag.

## Alternatives rejected

- **Trim Envelopes without a checkpoint:** breaks late joiners and ADR-0010 immediately.
- **Ask the Host to send its authority snapshot:** crosses writer and reader postures, omits render-only state/FeedLines, and turns a disposable gateway artifact into a new wire authority contract.
- **Put game folding in `room-wire`:** violates the lattice and the game-module seam. The injected opaque producer keeps `room-wire` transport- and game-neutral.
- **Keep every rendered FeedLine in the checkpoint:** preserves unlimited late-join scrollback but does not bound RSS; it moves growth from `Envelope[]` to strings and fails the issue.
- **Persist checkpoints:** makes game-derived state durable at the gateway, directly violating NQ-11.
- **Periodic full refolds:** bounds implementation complexity but creates CPU spikes proportional to Log length and does not make join work flat.

## Consequences

The gateway now genuinely shares folded render state, correcting the earlier envelope-history-only posture called out in `CONTEXT.md`. `packages/core` gains the opaque optional replay-checkpoint contract, `packages/table` owns its versioned checkpoint payload and producer, and `packages/room-wire` owns bounded tail/cursor mechanics. A checkpoint-backed Table batches its initial bounded replay into one projection update; live events and non-checkpoint stores retain on-demand rendering. Snapshot payload growth from legitimate current game state is irreducible; the bounded claim is specifically that **history overhead** is one current-state checkpoint + 100 FeedLines + 512 Envelopes (plus one bounded tail copy per joining view), not that an arbitrarily large current map/sheet/roster occupies constant bytes. The R9 history benchmark and a dated benchmark note become the reopening baseline.
