# room-wire: the RoomStore wire protocol gets its own package, and the connection authenticates the actor

Issue #8 productizes the RoomStore-over-iroh seam that #6 proved with a test-only adapter (`packages/room-host/test/remote.ts`). The definition places the seam ("one interface, two adapters — in-process store or iroh client") but never places the wire protocol: the workspace tree has no home for the iroh client, `transport-iroh` is pinned narrow ("iroh endpoint behind the narrow transport seam" — it deliberately has no `@supervillain/core` dependency), and `room-host` is the single-writer host, which the gateway (#9) must be able to avoid importing ("a doorway, not a landlord").

**Decision: a new package, `packages/room-wire`,** holding the whole wire story in one legible place: the JSON codec, `serveRoomStore` (the host's serving half, wrapping any `RoomStore`), and `connectRoomStore` (the iroh client adapter of the RoomStore seam). It depends on `@supervillain/core` and `@supervillain/transport-iroh` only — never on `room-host` — joins the Node-compat lattice set, and runs its specs under both Bun and Node like the rest of the wire-adjacent code. Splitting serve/connect across `room-host`/a-client-package was rejected: the two halves share the codec, and a protocol you can read in one package is worth more than a symmetric-looking dependency graph. Consumers: the CLI (`create` serves, `join` connects) now, the gateway (client half only) at #9.

**Decision: the connection authenticates the actor.** iroh connections are mutually authenticated by ed25519 keys, and our actor string _is_ an ed25519 public key (hex). The transport seam therefore exposes the peer's key (`TransportConnection.remoteId`, lowercase hex), endpoints can be seeded from an identity's secret key (`IrohEndpointOptions.secretKeyHex`, so NodeId == the identity's key), and `serveRoomStore` rejects any submission whose claimed `actor` differs from the connection's `remoteId` — key-as-account enforced at the wire, not trusted from the payload. The wire still carries the actor field end-to-end (rather than the server silently stamping it) so a client-side identity bug surfaces as a rejection instead of being masked.

The protocol itself (framed JSON over the transport seam, per-purpose connections opened with a `hello`) adds an `info` channel (`{ gameId, label }`, for a joiner to pick its view entry and title its table before attaching) to the proven `submit` (lockstep request/response) and `stream` (credit-based, resume = a fresh connection with `fromSeq`) channels. Reconnection lives in the client adapter: the stream re-dials with backoff from the last delivered seq and dedupes on seq, so a fold downstream never sees a gap or a repeat; submissions are never auto-retried (a resubmitted dice roll is a different roll — the failure surfaces to the caller).

**Revisit trigger:** if the gateway's proxy (#9) or the browser bridge (v3) needs a second transport under this protocol, the codec/channel layer may split from the iroh-specific dialing; don't pre-build that seam.
