# Capability token: derived secret, hash-at-rest, redaction fences, and the token-handle pre-commitment

Resolved on [Capability token spec (#102)](https://github.com/oscabriel/supervillain/issues/102), 2026-07-30. [ADR-0009](./0009-capability-url-and-publish-contract.md) made the capability URL the sole web access model, made `publish list` the lost-URL recovery surface, and derived OG image URLs from the token; [ADR-0013](./0013-server-data-layer-gateway-owned-identity-and-two-stores.md) put `capability tokens` and `dead-token tombstones` in the backend store; [#31](https://github.com/oscabriel/supervillain/issues/31)'s research flagged the token's security posture as the framework-independent spec that must precede the routes; [#87](https://github.com/oscabriel/supervillain/issues/87)(e) added the token-handle question from the exe.dev precedent (`.agents/research/exe-dev-precedent.md` §13). This is the implementation contract for the publish API ([#104](https://github.com/oscabriel/supervillain/issues/104)), artifact pages ([#106](https://github.com/oscabriel/supervillain/issues/106)), and OG cards ([#107](https://github.com/oscabriel/supervillain/issues/107)). It rises to ADR rather than a side-doc because one decision adds a precious operational secret and corrects a durable-list row in ADR-0013.

**Decision: the token is 32 bytes, base64url unpadded — a 43-character path segment.** `/a/:capability` where the segment is exactly 43 characters over `[A-Za-z0-9_-]` (RFC 4648 base64url, no padding), encoding a 32-byte value carrying full 256-bit strength. Guessing is defeated by entropy, not throttling: no token-specific rate limit is required, online or off, and none is added. Requests whose segment fails the length/alphabet check short-circuit to the same generic 404 as everything else below — the format is public knowledge, so the short-circuit leaks nothing.

**Decision: the backend never stores a token — it stores a seed and a hash, and derives the token when the owner asks.** At mint, the backend draws a 32-byte `seed` from the runtime CSPRNG and computes `token = HMAC-SHA256(k, seed)`, where `k` is the **web token key**: 32 bytes, generated at the web deployable's first boot if absent (mode 0600), a **file, never a row** — the gateway host key's precious-file class from [#40](https://github.com/oscabriel/supervillain/issues/40). The artifact row stores `seed` and `token_hash = SHA-256(token)` (unique, indexed — the hot lookup); the plaintext token exists only in the mint/list response to the authenticated owner. `k` must live **outside the Litestream/restic backup set** and be **escrowed off-box separately** from the database replicas — otherwise one leaked backup reassembles every token. The split is the point: the database alone (seeds + hashes) yields no token, `k` alone yields no token, and the pair is exactly what lets `publish list` keep ADR-0009's promise — it **reconstructs** each URL as `HMAC-SHA256(k, seed)` per live row and returns type, name, full URL, published-at, unchanged. Because derivation depends only on the row's seed — never on identity, name, or type — re-publish (same row, untouched seed) keeps the URL stable by construction, and identity linking can never break or change a URL (the derivation-from-`(owner, type, name)` alternative was rejected for exactly those two collisions, besides conflicting with fresh-mint-after-revoke). Plaintext-at-rest was rejected because the store replicates continuously to third-party storage and pages update in place: a leaked replica would be a **standing live credential** granting future reads the owner cannot see or detect, where hashes confine a leak to the data in the leak. Random-token-plus-AEAD-ciphertext was rejected as isomorphic in columns and security while adding nonce handling for nothing. Disaster-recovery honesty: restoring database + files restores reads (hashes present); restoring `k` from escrow restores `list`; losing `k` leaves every existing URL working but **permanently unlistable and unrecoverable** — re-minting would change shared URLs — so the escrow is load-bearing, stated here rather than discovered. No key-rotation mechanism ships at v1: a suspected compromise of `k` alone exposes nothing without the seeds, and the answer to a suspected joint compromise is the owner-visible one that already exists — revoke and re-publish mints fresh.

**Decision: one lookup path, one 404 — revoked and never-existed are indistinguishable.** `GET /a/:capability` hashes the presented token and performs the indexed lookups against live rows **and** tombstones on every request (both, or one union query — never an early return that skips the tombstone check), so revoked and never-existed share a code path, a status (always 404, never 410, never a "this was revoked" page), a body (the web app's one generic not-found), and headers. No constant-time comparison ceremony is required: an indexed lookup over unsalted SHA-256 of 256-bit-strength tokens is not oracle-usable (a hash-prefix timing signal does not invert toward a preimage), and **unsalted is deliberate** — salting defends low-entropy secrets and would break the indexed lookup; these tokens are not low-entropy.

**Decision: three headers on every `/a/*` response, 200 and 404 alike.** `Referrer-Policy: no-referrer` — an artifact page must never leak its own URL to any outbound destination. `Cache-Control: private, no-store` — pages update in place on re-publish and die instantly on revoke (ADR-0009), so no shared cache may hold one and no browser may serve one stale; the cost is that every view is an SSR hit, which is one indexed SQLite lookup, the workload [ADR-0020](./0020-web-stack-tanstack-start-pages-mounted-hono-api-one-process-on-the-vps.md) already sized. `X-Robots-Tag: noindex` (plus the matching robots meta on the page) — the link is the permission, and a capability URL pasted somewhere public must not become findable-by-search; an index would republish the permission. ADR-0009's honest limitation stands untouched: chat apps cache unfurls, and revoke cannot recall previews already rendered into chat history.

**Decision: capability tokens join the never-logged class, with two named enforcement fences.** ADR-0013's mirror — game content never in logs, metrics, telemetry, or crash reports — gains capability tokens as a member. Fence one, **Caddy**: the web vhost's access log uses the `filter` format — `request>uri` is replaced for `/a/*` requests (the line survives for ops; the path becomes `/a/REDACTED`) and the `Referer` request-header field is deleted from logged fields wholesale. Redact, don't skip: dropping `/a/*` lines entirely would hide abuse traffic; redacted lines don't. Fence two, **the app logger**: one middleware establishes that the loggable identifier for capability routes is the route pattern (`/a/:capability`, the literal string), never the concrete URL; error handlers and any future error reporter scrub the same way; the 404 body never echoes the request path. No analytics exist on artifact pages at v1, and any future addition inherits the same rule — route pattern, never concrete path. The token appears in exactly one place: the mint/`list` response to the authenticated owner, and the CLI printing it.

**Decision: revoke, restated against this storage.** Revoke writes the tombstone (`token_hash`, kept forever) and deletes the artifact row, the snapshot file, and the OG PNG. A later publish of the same (owner, type, name) is a new row with a new seed — ADR-0009's fresh-mint-never-resurrect holds by construction, because the old hash stays tombstoned and can never validate again. _(Settled 2026-08-03, [ADR-0029](./0029-publish-authority-automation-consent-and-operator-takedown.md): an **operator takedown** uses this exact permanent path — the same tombstone, Artifact-row deletion, snapshot deletion, OG deletion, and generic 404. It is Artifact-specific and does not block a later fresh Publish.)_

**Decision: the token-handle pre-commitment (#87e).** Any future short or pretty share link is a **handle validated through the real token on every use** — resolve handle → real token → the same hash lookup, tombstones included — so there is exactly one revocation point and revoking the token kills every handle with it. **No second secret in a second table, ever**: the naive second-secret build inherits none of the tombstones and is precisely how ADR-0009's forever-revoke promise would break silently (exe.dev's exe1-over-exe0 shape, verbatim). The alternative that avoids minting a second form at all — `--qr` on the publish output ([#86](https://github.com/oscabriel/supervillain/issues/86)'s flag table) — remains open. This is a pre-commitment, not a build: no handle ships until someone actually asks for one.

**Decision: the OG image URL is a child path of the token.** `/a/:capability/og.png` — the same token, the same lookup, the same generic 404, the same headers, and the same redaction fences (the Caddy `/a/*` match covers it). Exactly as unguessable as the page, revoked together with it, no separately-guessable image path — ADR-0009's pin, made concrete. The persisted PNG on disk is keyed internally by artifact row, never by token, so re-publish regenerates it in place behind the stable URL; the generation pipeline is #107's, only the URL shape and its safety posture are pinned here.

**Consequences:** ADR-0009 gains a dated pointer to this contract; ADR-0013's durable-list row `capability tokens` is corrected in place (seeds + hashes, never plaintext) and the web token key joins the file-not-a-row precious class, which adds an escrow item to #40's list — escrowed **apart from** the database replicas; the web deployable's ops artifacts gain the Caddyfile log-filter block and the first-boot key generation; #104 implements mint/list/revoke and the unified 404 against this document; #106 implements the headers, the 404, and the app-logger fence; #107 implements the `og.png` child path.

**Revisit triggers:** a real request for a short/pretty link fires the handle build under the pre-commitment above (or `--qr`, and no second form ever); a suspected joint compromise of `k` and a database replica forces the key-rotation mechanism this ADR deliberately omits; observed scraping or abuse of `/a/*` reopens rate limiting (entropy, not throttling, is the guessing defense until then).
