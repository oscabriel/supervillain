# One vocabulary, doorways by authority: the command grammar and the flag policy table

> **Amended 2026-07-30 by [ADR-0024](./0024-publish-http-surface-is-rest-shaped-command-endpoint-retired.md):** the backend's HTTP surface decision below (one command endpoint, command line as the encoding) and the "parallel REST resource design" rejection row are corrected — the publish surface shipped and stands REST-shaped, for reasons recorded there. Every other decision here (doorways by authority, the flag table, no SSH one-shot wire, the no-PTY notice) stands.

Resolved on [One grammar, three doorways (#86)](https://github.com/oscabriel/supervillain/issues/86), 2026-07-28, from the exe.dev precedent read (`.agents/research/exe-dev-precedent.md` §2, §7.1, §9.1). exe.dev's load-bearing idea — the API _is_ the SSH CLI, the same verbs through an interactive REPL, a one-shot `ssh` command, and an HTTP POST — cannot transfer literally, for two facts established during grilling. First, the gateway exposes no HTTP surface, by ratified decision (ADR-0005 as amended 2026-07-25), and its SSH door (`@opentui/ssh`, #62) rejects exec requests deliberately — upstream declined a generic exec hook in [opentui#1186](https://github.com/anomalyco/opentui/issues/1186), closed not-planned: the package is for renderer-backed TUI sessions only, and the rejection is tested in their integration suite. Second, and deeper: exe.dev's product lives on their servers, so every verb works through every door; our three pinned table verbs are all local-machine acts — `create` starts the Host on the GM's machine, `publish` reads the GM's campaign folder, `join` is constitutively interactive. What transfers is the discipline, not the topology.

**Decision: one vocabulary, doorways assigned by authority.** Any act whose authority lives gateway-side or backend-side is invoked by the same name with the same flags through the doorways of the side that owns it: gateway-authority acts get a Lobby screen and a CLI verb; backend-authority acts get the CLI verb and the backend's HTTP command endpoint it rides. Acts whose authority lives on the GM's machine (`create`, `publish` push) or that are inherently interactive (`join`) are constitutively local and are never promised on remote doors — the absence is named in docs with the user-side answer, not papered over. The pinned verb set (`create` / `join` / `publish`) is untouched; this decision adds doorway semantics, it does not reopen vocabulary.

**Decision: the doorway assignment is a rule, not a list.** Every gateway-authority act ships its Lobby screen and CLI verb the day it lands; every backend-authority act ships its CLI verb over the command endpoint. A command may be deliberately withheld from a doorway only when it is a human-consent act, and the withholding must be recorded with its reason — exe.dev's `grant-support-root`-has-no-`--json` move. The first expected use is the support observer toggle (#92); the propose-vs-run agent list (#87) will lean on the same clause. The initial set falls out of what exists: `whoami` (#90) first, `key link` next, `doc` if #37 adopts it — each as a Lobby screen and a CLI verb.

**Decision: each door speaks only for the state it owns; the gateway→backend conduit is deferred.** `publish list` and `publish revoke` have their authority in the backend (ADR-0009: sole truth for publish state), so they ride the backend's door, not the gateway's. The Lobby carries gateway-authority acts only. **Churn row (explicit demand trigger):** a gateway proxy for backend-authority verbs — reopened only if a real "check or revoke my URLs from a machine without the CLI" need appears; anyone who can publish already has the CLI on that machine, so symmetry alone is not a reason. ADR-0013 removed the last gateway→backend hop; reintroducing one requires better evidence than aesthetics.

**Decision: the backend's HTTP surface is the command vocabulary, one endpoint, command line as the encoding.** When publish ships, the CLI→backend transport is the public API: one command endpoint whose body carries the command line exactly as typed (`publish log <room> --json`), plus a payload part used only by `publish` push (bounded by ADR-0009's artifact cap). `--json` semantics are identical to the CLI, and machine callers always get JSON. Authentication is the key signature — possession of the key is ownership (ADR-0009); no web accounts. Any future token form follows the handle rule being grilled in #87 (validated through the key, one revocation point). The surface ships with an honest-limits page in the §11 style: every limit names its recovery as a command in the same breath — timeout, the artifact cap, no interactivity, no streaming. Everything below that contract line — endpoint path, multipart vs header encoding — is implementation and may change without reopening this ADR.

**Decision: the flag policy table.** A flag is a type declaration about the command, and absence carries meaning: no `--json` declares a command held or interactive, not an oversight.

| Command | `--json` | `--qr` | `--yes` | Type declaration |
| --- | --- | --- | --- | --- |
| `create` | no | no | no | Holds the table — a long-running TUI; it becomes the table rather than returning output. |
| `join` | no | no | no | Spawns real `ssh`; constitutively interactive. |
| `publish <type> <name>` | yes | yes | no | Exits with a Capability URL; re-publish updates and revoke exists, so not irreversible. |
| `publish revoke <type> <name>` | yes | no | yes | The only permanently irreversible act (ADR-0009). Prompts interactively; `--yes` is the documented non-interactive bypass, its help string naming what it skips and who needs it. |
| `publish list` | yes | no | no | Pure query; doubles as lost-URL recovery. |
| `whoami` | yes | no | no | Pure query; identical output on both doorways. |

Three general rules govern everything not enumerated: (1) every command that exits with output gets `--json` — covering `key`, `map`, `campaign`, `character` without more rows; the meaning-carrying exceptions are exactly the held/interactive set (`create`, `join`, `gateway serve`) plus recorded human-consent withholdings; (2) `--help` composes with `--json` on every command _including_ the no-`--json` ones — help is output even when the act is interactive; this machine-readable introspection is the Agent-surface feed, the "file is the API" move applied to the command line; (3) `--qr` appears wherever a Capability URL is emitted and nowhere else. **Churn rows:** a QR on `create`'s summon block (players scanning the join line onto phones); a headless/scripted `create` — the table's deliberate `--json` absence makes that gap visible, and filling it is a new decision, not a bug fix.

**Decision: no SSH one-shot wire.** The third doorway exe.dev gets from exec — scripts driving the gateway over one-shot SSH — is forgone, on the topology facts above: the entire gateway-authority surface is a handful of low-frequency acts, every one of which ships interactively in the Lobby and in the CLI, and the distribution invariant (one downloaded file, never "install a runtime") puts the CLI a curl away from any machine that can script. The CLI-less-scripting need is unmeasured and expected rare; the wire would be a permanent second dispatch path — no-PTY detection, line parsing, `--json` parity, exit-status semantics — bought on spec. SSH exec requests remain rejected: that is upstream's documented, tested contract, and after opentui#1186 we accept their scope rather than proposing again or side-stepping the library (#62's decision stands). The natural `ssh supervillain.app whoami` syntax therefore fails, and the docs name that absence with its answer — the act exists in the Lobby and the CLI. **Churn row (explicit demand trigger):** if measured demand appears for scripting the gateway from CLI-less machines — agents are the expected source — the cheapest re-entry is the piped-stdin no-PTY shell dispatcher, whose ratified shape is recorded here so it never needs re-deriving: `echo "whoami --json" | ssh supervillain.app`, the Lobby detects the absent PTY and runs a line-oriented dispatcher over the same vocabulary. Its two feasibility questions — a clean byte stream from a session that never starts its renderer, and exit status on a shell channel — were the withdrawn spike's, and reopen with it. The username-verb form (`ssh whoami@supervillain.app`) is noted and set aside: it works with the door library today, but carries no flags and spends the verb namespace in the registry for a cosmetic saving.

**Decision: the no-PTY honesty notice.** A shell session that arrives without a PTY gets one plain-text line — "this door is interactive; run `ssh -t`, or use the CLI for scripts" — and a clean close, instead of a renderer's escape stream. No parsing, no dispatch, no `--json`: the notice is the whole of the wire's residue, and it exists so a script's mistake fails legibly in the product's voice rather than as garbage bytes.

## Alternatives rejected

- **An SSH one-shot wire (piped stdin, exec, or username-verb):** unmeasured convenience against a permanent second dispatch path; forgone with a trigger-gated re-entry recorded above, not scheduled.
- **A fixed doorway-per-verb list:** every addition reopens the decision; the rule with a recorded-exception clause does not.
- **An HTTP command door on the gateway (full exe.dev):** contradicts the ratified no-HTTP gateway surface and fails ADR-0009's web-surface test — nothing there that SSH cannot carry.
- **Committing to the gateway→backend conduit now:** designs a relationship against an unpicked stack (#31/#32) on a weak demand signal; ADR-0013 just removed the only such hop.
- **A structured-envelope HTTP encoding (`{argv: […]}`):** breaks the property that pays for the whole design — the HTTP body is the command line, so a call is debuggable by pasting the exact line you ran in the terminal.
- **A parallel REST resource design:** two APIs to learn, drift guaranteed.
- **Proposing `.onExec` upstream:** exactly this ask was declined in opentui#1186 as out of the package's renderer-backed scope; sequencing our surface behind a request already refused once makes the roadmap hostage to a dependency we do not control.
- **Hand-rolled exec handling beside the bridge:** reopens #62's "no hand-rolled ssh2 at the door" for a convenience syntax.

## Consequences

`whoami` (#90) ships as Lobby screen + CLI verb, gated on nothing. The spike filed from #86 ([#93](https://github.com/oscabriel/supervillain/issues/93)) is withdrawn with the wire and closes won't-do. Publish implementation (ADR-0009) inherits the table above — `--yes` on revoke and `--qr` on push are now contract, and its HTTP surface must be the command endpoint, not REST. #37's docs scope gains the honest-limits page; #91's generated room name inherits `create`'s deliberate `--json` absence; #87 inherits the recorded-exception clause, the `key link` mint question, and the token-handle rule. The gateway gains the no-PTY honesty notice as a small Lobby-side item. The exceptions column of the flag table is small and load-bearing — additions to it are decisions, recorded here or in a successor.
