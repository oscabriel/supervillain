# Fold posture: writers halt, readers tolerate

Resolved on [Fold posture: known-invalid events — host rejects, the table fold skips (#47)](https://github.com/oscabriel/supervillain/issues/47), 2026-07-21. Surfaced by the deep review of the #24–#28 play-support lane: the host fold throws on known-invalid core history while the table fold trusts the same envelopes via casts and silently skips an unknown-seat `core.character-bound` — on the same log the two folds can disagree, producing an apparently healthy but incomplete table. "Skip unknown future events, reject known-invalid events" was stated nowhere and implemented inconsistently. This ADR pins the contract.

**Decision: every fold classifies events into two tiers, keyed on type recognition.**

- **Unknown** — the fold does not recognize the envelope's `type`: a `core.*` type outside the fold's vocabulary, or a game type outside the module's event grammar. This is deliberate forward compatibility for version skew.
- **Known-invalid** — the fold recognizes the type but the event violates what the fold knows must hold: a malformed payload (missing `seatId`, non-object game payload) or a fold-invariant violation (binding a character to an unknown seat, a duplicate seat claim).

Classification is **per fold**, not a global verdict per event: host, table, gateway, and each module recognize types independently, so the same envelope can be unknown to one fold and known-invalid to another. The contract is a posture per fold.

**Decision: the posture is a function of holding the pen — writers halt, readers tolerate.**

- **Authority fold (the host): halt on both tiers.** Known-invalid → refuse to open the log (current behavior, kept — replay throws with a line-precise error). Unknown type → **also refuse to open**, with a line-precise error naming the type ("this host is too old"). This is a behavior change: today the host silently ignores unrecognized `core.*` types and unknown game events hit the module's silent skip. A single-writer authority must never fold past anything it can't fully interpret and then append on top of state it only partially understood — that bakes divergence into the canonical log forever, the same corruption class the #24–#28 review closed. Every future core event type is thus a host version fence; a downgraded GM binary refuses to open a newer log until re-upgraded. No read-only escape hatch.
- **Render folds (the table today, the gateway's fold when it exists): never halt.** A reader holds no pen and must not be brickable by one bad line — halting would hand any crafted or skewed event a denial-of-play lever over every connected client. **Unknown → silent skip** (an older client at a newer host's table quietly misses events it was never taught; quiet degradation is the accepted cost — an "unknown event" notice would spam every legacy client the moment a host ships one new type). **Known-invalid → loud skip.**

**Decision: loud = a warning-toned FeedLine carrying seq, type, and reason.** E.g. `⚠ skipped event #42 (core.character-bound): unknown seat 'ramona'`. Seq equals the JSONL line number in the campaign folder, so the warning points the GM at the exact offending file line. Bursts during initial replay (a systemic problem) collapse to one summary line (`⚠ 17 events skipped during replay (first: #42 …)`). No persistent chrome badge at v0 — the feed is the shared surface that exists; a scrolled-away warning is the accepted residual (a late joiner can still face an incomplete table with the warning gone). Consequence: the table fold's currently-silent known-invalid cases — unknown-seat `core.character-bound` and the non-object-payload drop — are promoted to loud.

**Decision: shipped shapes fold forever.** Any event shape a **released** host ever legitimately appended stays in the recognized-and-valid tier of every future fold, core and module alike. Evolution happens by **upgrade-on-read** — the fold widens to accept both shapes and normalizes the old one at fold time (the `sheetOfEnteredEvent`/`upgradeStatBlock` precedent from the legacy replay fixes). Never log migrations, never rewriting the campaign folder (a migrated folder would no longer open on the older binary that wrote it, violating "the campaign folder is canonical and portable"). Corollaries: the known-invalid tier is by definition reserved for shapes no released host ever wrote; an event type name can never be reused with different semantics; every schema change adds a permanent legacy-upgrade branch backed by permanent old-log fixtures in the test suites. The promise attaches at the first public release — pre-release/dev-era shapes (like the `statBlock`-shaped `ds.character-entered`, which is supported anyway) carry no formal guarantee before that line. This discipline is per module and not mechanically enforceable by the lattice; a module that breaks it strands its own old campaigns.

**Consequences:** the definition gains a dated correction acknowledging the render-side posture; the glossary gains **Fold posture**; implementation (loud-skip FeedLines with burst collapse, the two table-fold promotions, host halt-on-unknown with line-precise errors, old-log fixtures) is a separate implementation issue — until it lands, the code implements the pre-ADR state (silent skips, host ignoring unknowns). The practical reach of the divergence today is narrow (a crafted/custom RoomStore or version skew; `room-wire` validates envelope shape only), so the code fix is not launch-gating on its own.

**Implementation note (2026-07-25, [#53](https://github.com/oscabriel/supervillain/issues/53)).** The open mechanism question — how the writer fold recognizes module event types — resolved to the cheapest honest option: **each module declares an event grammar**, a flat list of every event type its fold recognizes (legacy shapes included, since a legacy shape is the same recognized type upgraded on read). The list rides on the module's authority entry beside `model` and `authority`, so the host can classify a game event without importing the module or asking `apply` to signal. It is a declaration, not a derivation, and the lattice cannot check it, so two guards back it: the host refuses to **write** an event outside the emitting module's own grammar (caught before the append, where it is still a bug and not a corrupt log), and each module's conformance test holds the list against what its authority emits. Core carries the matching list for `core.*` types. On the render side the replay window has no wire boundary — the RoomStore stream hands over the backlog and follows live without marking the seam — so the table treats the first quiet gap in the stream as the end of replay and flushes its collapsed warning there; erring short costs the collapse, never a warning.

**Revisit triggers:** a persistent "degraded" chrome badge if real play shows scrolled-away warnings hiding incomplete tables; a host read-only escape hatch if downgrade lockouts hurt real GMs; the gateway's fold inherits the reader posture verbatim when it is built — if it ever needs to diverge, that is a definition problem, not a patch here.

**Amended 2026-07-25 (grilling session, after [#53](https://github.com/oscabriel/supervillain/issues/53)).** #53's implementation promoted two cases beyond its issue's literal "shape checks": a **duplicate seat claim** and **an actor claiming a second seat** are loud skips on the table, not silent ones. Ratified. This ADR already names the duplicate claim known-invalid and the host halts on both, so a silent table would have preserved exactly the two-folds-disagree bug this ADR exists to close — where an issue's letter and this ADR's intent diverge, the ADR's intent wins, and the burndown applied that precedence correctly.
