# Offers: eligibility lives once, on the model entry

Resolved 2026-09-10, in-session triage of [#139](https://github.com/oscabriel/supervillain/issues/139), surfaced by the same tobi/neohack source read as [ADR-0035](./0035-standing-decisions-a-pending-choice-is-state-continued-by-its-own-command.md) (`~/Developer/clones/github.com/tobi/neohack` @ `b2e83ef`). This is the part of neohack's design that held up best: clients "do not duplicate terrain tables" — the client computes offers from the same code paths the operations use, as data, with a closed availability union.

**Decision: the `model` entry gains a pure eligibility projection, `offers(state, view): readonly Offer<C>[]`.** The lattice already forbids the render side from importing `decide`, which is right — but nothing told a Panel where an eligibility rule may come from. Left unanswered, the rule gets written twice: once in the module's `decide`, once re-derived in a Panel that does not import `decide` so the lattice passes. The two copies drift, and the player sees a Rejection for something the UI offered. `offers` is that rule's single home: a pure projection of `S` — no randomness, no TableView writes — on the entry point both `authority` and `view` already import. No new lattice edge. Every Panel reads the same offers, `decide` may pre-check them, and so would any future agent door.

**Decision: an offer is eligibility, never a guarantee.** Offers are computed from state at render time, and state moves between the offer and the command landing, so `decide` may still reject an offered command. neohack's line is adopted verbatim: "Eligibility does not imply safety. An eligible action is an attempt, not a safety guarantee." The conformance rule is deliberately **one-way**: every `attemptable` offer's command is accepted by `decide` on the same state, which makes "the UI offered it and authority refused it" a bug by definition, testable in the fake module's conformance suite. The reverse — `decide` pre-checking `offers` and rejecting anything unoffered with a uniform Rejection — is recommended, not required: a GM-only force command may be decidable without ever being offered to anyone, and a mandatory precheck would forbid it. One corollary is binding, though: a `blocked` offer's reason names a rule, so `decide` must enforce that rule, worded once and shared (the fake module exports `PLEDGE_OWN_SEAT_REASON` and both `offers` and `decide` use it). The first cut shipped a blocked "only your own seat can pledge" offer while `decide` accepted pledges for any seat — the drift this ADR exists to prevent, running the other way.

**Decision: availability is a closed three-way union, smaller than neohack's five, and `Offer<C>` discriminates on it.** `attemptable` carries `command: C` (dispatchable now), `needsSelection` carries `template: Partial<C>` (a fill-in; the Panel completes it — exactly the ADR-0030 contextual text task shape, where the Panel's converter produces the finished command), `blocked` carries `reason: string` and no command. The issue's sketch had one interface with `command?: C` doubling as the template; the first implementation showed why that is wrong: to typecheck an incomplete template as `C`, the fake module had to make `answer` optional on its answer command, and `decide` grew a runtime branch refusing half-filled commands. Draw Steel would have inherited that for every templatable command. Typing the template `Partial<C>` keeps the module's command union whole, and the discriminated union makes "blocked requires a reason" a compile error rather than a doc sentence. neohack carries `uncertain` and `outOfReach` because its driver projects perceived-only observations; there is no perception uncertainty here — state is authoritative and shared, so the tiers that exist to express doubt are dead weight. `blocked` offers exist so a Panel can show a disabled action with a reason instead of hiding it (ADR-0030's contextual key help wants that text). Labels and reasons are module-owned strings; core defines the `Offer` shape, the module owns the words — the ADR-0025/0031 strings-only posture, unchanged.

**Decision: the standing-decision gate lives in `offers`.** A seat with a standing decision ([ADR-0035](./0035-standing-decisions-a-pending-choice-is-state-continued-by-its-own-command.md)) collapses its offer list to answering or declining that decision — the input-gate instinct neohack's driver has, expressed as ordinary projection logic. When both conventions land, `offers` is where the gate shows up.

**Decision: the lattice's `game-model-imports-nothing` rule is amended, narrowly.** `offers`'s signature names core-owned seam types (`Offer`, `TableView`), so a game's `model.ts` imports `@supervillain/core` type-only — erased at compile time, no runtime edge. dependency-cruiser cannot distinguish a type-only import at the workspace-link boundary (the dependency resolves to the bare specifier, classified `unknown`), so the rule admits `@supervillain/core` from game model entries and a runtime core import remains a review-level violation the ruleset text records. Nothing else is permitted. _(Correction applied to `monorepo-stack.md` rule 4, 2026-09-10.)_

**Adoption is optional on the interface, deliberately.** `offers` is optional on `GameAuthority` so Draw Steel is not forced to invent decision kinds or eligibility rules before its v0 Panels exist — the issue's scope line, kept: the point is that the second copy of a rule cannot get written before the seam says where the first one lives. The Draw Steel adoption is a named-churn ledger row, not silence.

**Consequences:** `packages/core` gains the `Offer`/availability types and the optional `offers` member on `GameAuthority` and both entry Picks; the fake game module implements it and carries the conformance tests (every `attemptable` offer accepted by `decide` on the same state, on both sides of the gate; the gate collapse; a `blocked` offer whose reason `decide` refuses with, word for word); `.agents/CONTEXT.md` pins **Offer** (avoid: guarantee, eligible action, permission); the seam doc's entry-point table and Authority end gain the projection. Draw Steel is untouched in this pass.

**Revisit triggers:** a Draw Steel (or Mothership/Mörk Borg) Panel re-derives an eligibility rule from `S` (→ that is the trigger to adopt `offers` there); a `needsSelection` template demands richer fill-in metadata than the command itself carries (→ widen `Offer` one field at a time, recording each widening here); a second render surface (a future agent door) disagrees with a Panel about what is attemptable (→ same bug-by-definition rule as Panel drift, enforced the same way); state ever stops being authoritative and shared (→ the premise for rejecting neohack's `uncertain` tier dies with it — reopen the union).
