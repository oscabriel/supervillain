# Battle maps: core-owned surface, plain-text map files, inline capture into the log

Resolved on [Battle maps at v1: scope and artifact model (#39)](https://github.com/oscabriel/supervillain/issues/39), 2026-07-21. The 2026-07-18 correction moved battle maps into v1 but left everything about them open: what a map is, who owns it, what the artifact looks like, how it reaches the table, and whether publish covers it. The definition held that the FrameBuffer story, map artifacts, and their sharing model arrive together; this ADR is where they do. Rendering facts come from the [#38](https://github.com/oscabriel/supervillain/issues/38) FrameBuffer research (local: `.agents/research/38-framebuffer-battle-maps.md`).

**Decision: a v1 battle map is a terrain grid plus movable tokens — nothing else.** Fog of war, an in-app editor, and image import are cut to named churn. The fog cut is architectural, not cosmetic: hidden information in a shared, append-only log that every client refolds requires filtered projection touching host, gateway, and the replay promise — a question the definition has not opened, and one that must be opened deliberately or not at all.

**Decision: the map is core-owned.** With no rules adjudication in scope, the map is shared positional truth the GM manipulates freely — system-agnostic table furniture in the same category as chat, presence, and generic dice. Events are `core.map-*` / `core.token-*`; core chrome renders the map as its own region (not a slotted panel — slots place *module* panels); future game modules inherit maps for free; and the web artifact page renders a core-owned format with zero game imports, strengthening the "published snapshots need no game code" hope on the web lattice edge. The game-module seam does not change at all for v1 maps.

**Decision: the map artifact is a plain-text file whose body is the map.** `maps/<name>.map` in the campaign folder: a metadata header (name, legend) then an ASCII grid, one character per map cell. The legend maps author-chosen characters onto a core-pinned tile vocabulary (floor, wall, difficult, hazard, door), with a NetHack-informed default legend (`.` floor, `#` wall, `+` door, `^` hazard, `~` difficult). Terrain only — tokens are live-play state the log records, so the file never duplicates what replay already persists. Hard size bound ~200×100 cells keeps #38's wire estimates valid. Core owns the format and validator (the "schemas, never instances" spirit); GMs author every instance in their own editor, consistent with "character files are authored outside the app."

**Decision: entering play is full inline capture.** The GM issues a load command; the host — on the GM's machine, next to the campaign folder — reads and validates the file and appends `core.map-loaded` carrying the entire validated content (legend + grid rows) in the payload. The payload preserves the author's characters (the terrain's look) with semantics riding along in the legend. Last-loaded wins; `core.map-cleared` empties the surface. Replay never reads files: a mid-fight joiner folds the same map everyone sees. The rejected alternative — an event referencing the file by name/hash — breaks the log's self-containment and adds a content-distribution channel that doesn't exist.

**Decision: tokens are game-blind, and authority is GM-full / player-own-seat.** Token = id + glyph (one char) + label + position + optional **seat** binding. No game fields — a module badge (e.g. a DS condition marker) on a core token is real seam growth and sits in the churn ledger until a licensed churn point admits it; token↔character reach is transitive via the TableView character↔seat bindings (#21/#24). The GM places, moves, removes, and re-glyphs any token and loads/clears maps; a player may move only a token bound to their own seat — one authority check against the log-derived seat map. Events: `core.token-placed` / `core.token-moved` / `core.token-removed`.

**Decision: rendering stays inside the existing contracts.** Map cells compose exact-ANSI-16 theme tokens resolved once in core chrome — no second color contract (closing the palette question #38 flagged). One cell-grid `FrameBufferRenderable`: terrain as background + author glyph, tokens as foreground glyphs, hit-testing by coordinate arithmetic. One map cell = one terminal cell, NetHack-style; the ~1:2 aspect distortion is accepted. Keyboard-first manipulation everywhere; mouse click as progressive enhancement; no drag promise at v1 (#38 leaves drag unvalidated across clients and multiplexers).

**Decision: maps are the third publishable artifact.** `supervillain publish map <name>` snapshots the file's content — terrain only, never play state — to the web backend, minting a capability URL under the standard re-publish/revoke contract. Publish reads the file, not the log: you share your authored artifact, not a moment of play. The OG card is a terminal-styled mini-render of the map. Published session logs will contain inline `core.map-loaded` events; how a log page renders them belongs to the publish-contract decision ([#33](https://github.com/oscabriel/supervillain/issues/33)).

**Consequences:** core grows a vocabulary (map/token events, a chrome map region, map commands) but the seam does not; the CLI gains the `map` noun the 2026-07-18 correction promised; the web surface gains its simplest page type; #33 inherits the terrain-only artifact boundary; the battle-map prototype and implementation tickets named on [#29](https://github.com/oscabriel/supervillain/issues/29) are now specifiable.

**Revisit triggers:** all cuts are churn-ledger rows — fog of war (only when hidden-info-in-a-shared-log is deliberately opened), in-app editor + image import, richer-than-ANSI-16 palette + double-width cells (real GM demand plus #38's client-matrix validation), mouse drag (after that validation), module badges on tokens (licensed churn point), pre-placed token rosters (real prep demand). If a second game's maps ever need rules the core surface can't stay blind to, that is a definition problem, not a patch here.
