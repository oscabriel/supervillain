# One binary, two roles: the gateway role selector and the homelab state directory

Resolved on [One binary, two roles: make the self-hosted gateway the same compiled artifact (#65)](https://github.com/oscabriel/supervillain/issues/65), 2026-07-25. [ADR-0012](./0012-outbound-only-hybrid-drop-iroh-host-dials-out.md) (NQ-9, posture 2) says the self-hosted gateway is "the **same single compiled binary**, MIT, in the open repo, on a VPS or homelab box", and that this is what keeps "free to self-host, forever" literally true. It was not true of anything a user could download: `apps/gateway` was never compiled, the root `package.json` had no gateway compile script, `install.sh` fetched only the CLI, and the release workflow produced exactly one artifact per platform — the CLI role. This ADR records the shape that makes the claim true, and the two product questions the work surfaced: what the operator types, and where a homelab gateway keeps its state.

**Decision: one artifact, two roles — never a second download.** `bun build --compile` bundles the gateway's module graph into the same `supervillain` binary the release matrix already builds, ships, and checksums. Rejected: a second named artifact from the same build (`supervillain-gateway`). It would double the release matrix, the checksum rows, and the install ritual, and it would quietly weaken ADR-0012's sentence from "the same single compiled binary" to "a binary from the same repo" — which is a different, smaller promise. The one real cost is artifact size: every CLI user carries the SSH door and the broker server half they will never run. That is accepted, and it is the same trade the "same binary" sentence already made.

**Decision: `supervillain gateway serve` — a role selector, deliberately outside the pinned verb set, not a fourth verb.** The pinned set (`create` / `join` / `publish`) is the **table** surface: what a person at a table does. Serving a gateway is an operator act on a box, and the CLI already carries a management side outside the verb set — `key`, `character`, `map`, `campaign` are nouns with subcommands, landed by [#34](https://github.com/oscabriel/supervillain/issues/34), [#24–#28](https://github.com/oscabriel/supervillain/issues/24), [#46](https://github.com/oscabriel/supervillain/issues/46) and [#39](https://github.com/oscabriel/supervillain/issues/39). `gateway` joins that side. So the verb set is **not reopened and not widened**: no fourth verb, no re-pinning, no new player-facing surface. What is patched is the definition's phrasing, which read as though the three verbs were the CLI's whole surface — a documentation gap the management nouns had already outgrown, now stated once here rather than re-derived per ticket. Rejected: a bare `--gateway` flag on the top-level binary (invisible in help, and it collides with `create --gateway <addr>`, which means something else entirely — the address to dial); and `supervillain serve`, which reads like a fourth verb and would in fact be one.

**Decision: the two halves stay apart behind exactly one door.** `apps/gateway` is the server half — `bun:sqlite`, the SSH door, the broker — and a GM running `create` or a player running `join` must never evaluate a line of it. The seam is one file, `apps/cli/src/gateway-role.ts`, whose whole body is a deferred `import("@supervillain/gateway")`; a new dependency-cruiser rule, `gateway-role-behind-one-door`, makes it the only file in the workspace outside `apps/gateway/` permitted to name the package. The lattice was **amended deliberately**, as the ticket required, rather than left to pass vacuously: the arrow from client to server half now exists, is named, is singular, and is mechanically checked. The existing invariants are untouched — `bun:sqlite` still appears only under `apps/gateway/`, the render side still imports neither transport half, and the gateway still imports no `decide` and no `room-host`.

**Decision: the homelab gateway's state directory is `${XDG_STATE_HOME:-~/.local/state}/supervillain/gateway`, and nothing infers a posture.** Resolution order is `--state` beats `SUPERVILLAIN_GATEWAY_STATE` beats that default. It is never the campaign folder — the campaign is the GM's canonical files and travels between machines, while the gateway's identity, SSH host key, and registry belong to the box, which is ADR-0012's credentials-don't-travel rule one level up. [#40](https://github.com/oscabriel/supervillain/issues/40)'s `/var/lib/supervillain/` remains the **operated** box's path and is reached only by an explicit flag or environment variable that the deployment unit sets: the binary does not sniff uid 0, the hostname, or write access to `/var/lib` to pick a posture for the operator. That inference was rejected as a silent product decision — a daemon convention borrowed from elsewhere, not a decision this project has made. The path is exported as `OPERATED_GATEWAY_STATE_DIR` so the operated posture has one spelling to point at. A clean box has no state directory at all, so the role creates its own (mode `0700`) rather than demanding a provisioning step.

**Decision: the gateway role is the whole self-hosted surface — no web, no publishing, no Drizzle.** This preserves [ADR-0013](./0013-server-data-layer-gateway-owned-identity-and-two-stores.md)'s boundary rather than rediscovering it: the backend's ORM and store stay out of the downloaded artifact, which is what keeps it lean. Publishing is hosted-only at v1 — not because of our code, but because browsers do not do trust-on-first-use, so a capability URL served from a homelab box on the self-signed certificate [#64](https://github.com/oscabriel/supervillain/issues/64) mints would warn every recipient. Deferred, not forbidden, and the docs must say so plainly. What the self-hosted posture _does_ gain is the whole of play: because ADR-0013 made the gateway the complete identity authority for its own box — key-equivalence graph, revocation, link codes, all in its own store — a self-hosted deployment does key linking and GM roaming with no company backend in existence.

**Decision: the release smoke exercises the gateway role, not only the CLI role.** `smoke/gateway-smoke.sh` runs the downloaded artifact in the gateway role under `env -i` (no repo, no bun, no node, no leftover `SUPERVILLAIN_*`), waits for it to announce its address, asserts it created its own identity, SSH host key, and registry on a clean box, then runs the **same binary** in the CLI role against it — `create --name --gateway`, which reaches a live table only if the outbound pipe was accepted and the durable claim landed in the gateway's store — and finally stops it with `SIGTERM` and requires a clean exit. It runs on every platform in the release matrix, beside the existing CLI-role smoke. The claim "free to self-host, forever" is now tested against the artifact users actually download, which is the only place it was ever supposed to be true.

**Consequences:** `apps/cli` gains a workspace dependency on `@supervillain/gateway`, a project reference, and the one-file role door; `apps/gateway` gains `serveGateway` (the role runner), `parseGatewayRoleArgs` (its argument surface, testable without binding a port), and `resolveGatewayStateDir`. The gateway's former env-only `main()` becomes flag-first with the `SUPERVILLAIN_GATEWAY_*` variables demoted to fallbacks, and it now stops on `SIGTERM` as well as `SIGINT` — an always-on box is stopped by a service manager at least as often as by a human. `smoke/release-smoke.sh` takes optional extra `create` arguments so the gateway smoke can reuse it whole. `product-definition.md` gains a dated correction at the CLI-verb-set line; `CONTEXT.md` gains **Role**. No compile script per role is added: `compile:*` already produces the dual-role artifact.

**Deliberately not decided here:** the bind defaults are unchanged from the pre-existing gateway (`--bind` unset means the SSH door on `0.0.0.0` and the Host pipe on `127.0.0.1`), so a homelab Host running on a _different_ box from its gateway must pass `--bind` explicitly. Whether the Host pipe should be exposed by default in the self-hosted posture is a real question, and ADR-0012's homelab ritual ("one forwarded port + DDNS, the exposed protocol is SSH") reads as though it should not be — but changing a bind default is a security posture, not a packaging detail, and it belongs with [#64](https://github.com/oscabriel/supervillain/issues/64)'s self-signed-certificate and pairing-code work. `serve` is the role's only subcommand; a `gateway status` or `gateway migrate` would be additions, not reopenings.

**Revisit triggers:** a second artifact only if the dual-role binary's size becomes a measured download complaint; a fourth verb never (the management-noun side absorbs operator surfaces); the state-directory default only if a packaged distribution (a systemd unit, a container image, a Homebrew formula) needs a convention this order cannot express; the bind defaults on [#64](https://github.com/oscabriel/supervillain/issues/64).

**Measured 2026-07-25 (grilling session):** the laziness claim above is now observed, not assumed. A `console.error` marker at the top of the gateway module in a `bun build --compile` artifact never fires on the client path (`--version`, bare usage) and fires on `gateway serve --help` — Bun preserves dynamic-import laziness inside the compiled binary, so nothing on the client path evaluates the server half.
