# Capability URL + publish contract: stable URLs, identity ownership, self-describing snapshot documents

Resolved on [Capability URL + publish contract (#33)](https://github.com/oscabriel/supervillain/issues/33), 2026-07-21. The definition pinned publish = snapshot push, revocable by owner, capability URL as the sole web access model, no web accounts — but left the full contract open: URL identity and re-publish semantics, the revoke surface, ownership vs the key graph, the payload shape (and whether the web needs game imports), how log pages render inline `core.map-loaded` events (inherited from [ADR-0006](./0006-core-owned-battle-maps-and-inline-map-capture.md)), whether the web may use the glyph atlas (flagged by [ADR-0007](./0007-pixel-glyph-rendering-tier.md)), OG card contents, and retention. Everything here is framework-agnostic — the web/backend stack ([#31](https://github.com/oscabriel/supervillain/issues/31)/[#32](https://github.com/oscabriel/supervillain/issues/32)) remains open. _(Security contract located 2026-07-30, [ADR-0022](./0022-capability-token-derived-secret-hash-at-rest-redaction-and-the-token-handle.md): the capability token's format and entropy, derived-secret storage — hashes at rest, with `publish list` reconstructing URLs — logging redaction, response headers, the indistinguishable 404, the OG child path, and the #87(e) token-handle pre-commitment are all pinned there. Every decision below stands unchanged.)_ _(Authority and operator lifecycle settled 2026-08-03, [ADR-0029](./0029-publish-authority-automation-consent-and-operator-takedown.md): publish push remains non-interactive and harness-authorized; the GM is the sole publish authority with no per-character or age gate; every Publish carries the publisher warranty; and an operator takedown uses the same permanent tombstone lifecycle as owner revoke while leaving a fresh Publish available. The decisions below otherwise stand.)_

**Decision: a capability URL is stable per artifact — re-publish updates in place, revoke kills the URL forever.** An artifact is keyed by (owner identity, artifact type, artifact name). Re-publish overwrites the snapshot behind the same URL — the group-chat link stays current as the campaign evolves. Revoke deletes; the revoked secret is dead permanently — a later publish of the same name mints a fresh URL, never resurrects the old one. The accepted trade: a shared link is _live_ (holders see future updates), and the backend keys artifacts by durable identity.

**Decision: the room log is the publishable log unit; session structure is presentational.** The log is one JSONL per room and the glossary reserves "session" for the transport contract, so `supervillain publish log <room>` publishes the room's history as one artifact — no session-boundary event is invented. The log page renders day-break headings with stable, date-derived fragment anchors (`#YYYY-MM-DD`, UTC from envelope timestamps, `-2`/`-3` suffixes when multiple gaps share a date), so a GM can share `<url>#2026-07-21` as a deliberate session-scoped link. Fragments jump but don't trim, and never reach the server (the OG unfurl is always the whole-log card). **Churn rows (shared demand trigger, explicit interest recorded):** per-session-slice publish (would require a session-delimiter concept — a definition patch, made deliberately) and query-param filtered views (`?session-date=…` — brings per-view OG and caching questions with it).

**Decision: the CLI surface is `publish` sub-verbs in the #28 noun pattern, and the backend is the sole truth for publish state.** `supervillain publish <type> <name>` mints/updates (type set closed: `character` | `log` | `map`); `supervillain publish revoke <type> <name>` revokes; `supervillain publish list` shows everything live for your identity (type, name, URL, published-at) via an authenticated query over the same HTTP path [ADR-0005](./0005-key-linking-backend-registry-gateway-conduit-and-in-log-linking-events.md) established. The pinned room-verb set stays closed — no `unpublish`. No local receipts file: publish state is inherently backend state and a local copy would drift the moment another linked device revokes; the campaign folder stays campaign data. `publish list` requires network (the question is about a remote fact) and doubles as lost-URL recovery — possession of the key, not the URL, is ownership.

**Decision: ownership resolves through the key graph — artifacts belong to the identity, not the raw key.** Publish from the desktop, revoke from the linked laptop; `publish list` is unified across linked keys. Mechanism: request authenticated as a key, backend resolves key → identity via the ADR-0005 equivalence graph. _(Correction 2026-07-25, [ADR-0013](./0013-server-data-layer-gateway-owned-identity-and-two-stores.md): every decision in this ADR stands; only the mechanism moves. The graph is **gateway-owned**, so the backend resolves key → identity through a narrow interface with local and remote implementations rather than reading its own table — the hop lands on the cold publish path, never on authentication. Two consequences: publishing is **hosted-only at v1** (a self-hosted web role needs a real domain and CA certificate, because browsers cannot do trust-on-first-use — deferred, not forbidden), and a person who self-hosts their gateway but publishes to our web holds an identity with the **hosted** gateway too, since identity is per-gateway.)_ Edge: linking two identities that each published the same (type, name) never breaks either URL (capability URLs must not die as a side effect of linking); instead, re-publishing that name errors — listing both URLs — until the owner revokes one. Never silently overwrite, never silently break a shared link.

**Decision: the publish payload is a self-describing snapshot document; the web imports zero game code.** The CLI — which statically imports the full game packages anyway — folds all game knowledge into a **core-owned, versioned document vocabulary** at publish time: semantic sections and labeled fields for character sheets; per-event entries of FeedLine-style text runs (theme tokens, never ANSI) for logs; name + legend + grid for maps (per ADR-0006). Logs structurally force this (rendering events needs the module's `renderEvent`, in the `view` facet the web edge must never import); sheets choose it for **version skew**: a GM's binary pins their content version, and self-describing snapshots make that binary authoritative over what the page shows. This resolves the definition's "possibly _no_ game import at all" hope affirmatively — the web-framework fog's lattice edge tightens from "model + content only" to "no game imports for artifact pages." Costs accepted: presentation freezes until re-publish, and the document must stay semantic (sections/fields/runs, never pre-laid-out lines) so pages can reflow.

**Decision: log pages render `core.map-loaded` as an inline map-grid block — the ADR-0006 inheritance.** The document vocabulary gains one `map-grid` block (name + legend + grid) shared between map artifact pages and log pages. Log pages render it inline where the load happened, **collapsed by default** (map name as the summary line). Terrain-only: token events render as ordinary feed lines, never overlaid onto the grid — the ADR-0006 boundary holds. The terrain appearing in a published log is inherent to publishing a log that contains `core.map-loaded`; stripping it would falsify the play record. **Churn row:** a moment-by-moment board replay viewer (tokens included) is deliberately not attempted here.

**Decision: web map grids render as text in a self-hosted MonoMek webfont; the glyph atlas stays terminal-side.** The atlas exists only because ssh can't ship a font — the web can, and MonoMek is CC0. Map artifact pages and inline `map-grid` blocks render the text-tier grid (the author's legend characters) as real DOM text styled with MonoMek: the ADR-0007 identity on selectable, accessible text. This answers ADR-0007's flagged sub-question: importing the atlas web-side would be lattice-legal (pure data, zero game imports) but is **unmotivated** while the font itself is shippable. Coverage gaps fall back to a monospace font stack — symmetric with the terminal's per-glyph text-tier fallback. The terminal's quadrant rasterization and the raw font will differ subtly at small sizes; accepted — two tiers of one identity, not pixel-contract twins.

**Decision: OG cards render a core-owned `card` section of the snapshot document; image URLs derive from the capability token.** The CLI fills the card section at publish time — title, short description, a few label/value pairs, an optional glyph + accent hint (strings only), and the grid for maps — so the server-side generator stays exactly as game-blind as the page renderer. One terminal-styled template per artifact type with distinct colors/decoration: character (name, module-supplied descriptor line, a few stats, token glyph/color), log (room name, date range, session/event counts), map (mini/section render of the grid — the ADR-0006 pin — with dimensions). OG image URLs are derived from the capability token: exactly as unguessable as the page, revoked and regenerated together, no separately-guessable image path. Honest limitation, stated in revoke UX copy: chat apps cache unfurls — revoke kills the link, it cannot recall previews already rendered into chat history.

**Decision: no expiry; ops-tunable size cap; render-every-version.** Published artifacts live until revoked or overwritten — the link _is_ the permission, and permissions don't rot; `publish list` keeps exposure visible under the no-accounts model. The backend enforces a per-artifact size cap at publish time with a clear structural CLI error; the initial cap is 10 MB, explicitly an operational number, not a contract _(storage located 2026-07-25, [ADR-0013](./0013-server-data-layer-gateway-owned-identity-and-two-stores.md): snapshot documents are **files on disk under `/var/lib/supervillain/`** with database rows pointing at them, never blobs in the database — the tree #40 already backs up, and it keeps the store small enough for continuous replication)_ — a campaign log hitting it is the demand trigger for the per-slice churn row. Snapshot documents carry an integer schema version; the backend stores raw documents and renders every version it has ever accepted. Launch ships exactly version 1; version retirement policy is deliberately fog until a version 2 exists.

**Consequences:** the snapshot document schema becomes a core-owned versioned wire contract (an envelope-like promise on the web edge); the CLI gains `publish` sub-verbs and per-type document producers; the module seam gains a strings-only card-descriptor nomination (no schema growth); the web surface gains one generic document renderer for all three page types plus a self-hosted MonoMek asset; #29's v0→v1 migration item ("versioning of published snapshots") is answered; the churn ledger gains four rows (per-slice publish, query-param filtered views, board replay viewer, snapshot-version retirement policy — the last as named fog).

**Revisit triggers:** real demand for "share just one night" or a campaign hitting the size cap fires per-slice publish (and the session-delimiter definition patch it requires); filtered views fire with it; a snapshot-document version 2 forces the retirement-policy fog open; if the browser terminal (v3) or any future surface needs richer web rendering than the document vocabulary allows, that is a definition question about the web edge, not a patch here.
