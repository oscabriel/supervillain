# Authority handoff design: in-log seat transfer, epoch fencing, claim follows the log

Pinned at triage of [#136](https://github.com/oscabriel/supervillain/issues/136) with oscar, 2026-08-22 — a grilling session over the five open questions [ADR-0033](./0033-ownership-lives-in-format-not-topology-sovereignty-invariant-and-log-egress.md) left on the ticket. Codebase facts that shaped it: `gmSeatId` is a hardcoded constant claimed once at room creation and no transfer event exists; the fold throws on double claims; the gateway's durable registry refuses any claim by a different identity while same-identity re-registration silently supersedes whatever is live (last-registrar-wins, no seq comparison anywhere); the host pipe loop redials forever with backoff; map file reads are the only runtime campaign-folder access and degrade to clean Rejections when files are missing; character sidecars are CLI/publish-side only — the Host never reads them.

**Decision: the GM seat migrates through an in-log transfer event.** Handoff appends a new `core.*` event carrying the seat, the outgoing actor, the successor actor, and the successor's replay head (the takeover seq). The seat transfers — it never co-exists, so one-seat-per-key stays intact and the fold learns one new move instead of a second authority channel. Rejected: delegate stamping (smuggles commands around `decide`'s TableView checks and makes the Log lie about who acted) and a second GM seat (violates seat rules). Because the handoff is itself an Envelope, byte-identical replay reproduces it — which is the entire reason this direction costs nothing.

**Decision: any current Seat holder may resume.** Symmetric with #135's pinned pull authorization. Nominated successors were rejected: nomination machinery fails at exactly the moment handoff exists for (a GM gone without nominating), and at a friends-table the door already gates who holds a Seat. The act is loud by construction — the transfer event renders in every feed.

**Decision: the resumed room runs log-only.** No sidecar machinery. Future `core.load-map` commands against files the new folder lacks reject cleanly ("No map file…") until someone copies `maps/` over or authors fresh; character sidecars are irrelevant to hosting and stay wherever they are. This is today's code behavior; handoff adds documentation, not features. Rejected: widening #135's pull to carry sidecars — that contract ("plus nothing else") was pinned days ago for marginal benefit.

**Decision: the registry claim follows the log.** A resumer registers by presenting the transfer event as proof, and the durable `name → owner identity` claim moves to their identity. The door keeps working unchanged — same name, new machine behind it. Rejected: delegate registration under a derived name (breaks the door; disperses the table). This converts the registry from remembering authority to verifying it.

**Decision: fencing ground truth is the in-log epoch.** The transfer event records the takeover seq; any Host whose Log ends before that point — anyone not holding the event — is fenced, refused at registration, and loses any fork encounter against the chain containing the latest valid transfer event. No liveness proof is required or possible (asleep vs. dead is indistinguishable, and trying would be worse). This works with supervillain.app unreachable because it is a property of the artifact, not of our servers — Sovereignty invariant holds. Rejected: generalizing today's last-registrar-wins (a waking GM laptop would silently supersede the resumed room).

**Decision: fenced hosts stand down terminally.** The forever-redial loop must treat a fencing refusal as final: enter a stand-down state ("authority moved on at seq N"), never retry. The old GM keeps their Seat — seats live in the Log — so they can always take the room back by an ordinary resume under the any-seat-holder rule.

**Decision: orphaned events are lost deterministically, salvageable manually, never merged.** If the old Host was partitioned rather than dead, events it wrote past its last observed seq exist only on its disk fork. The stand-down message states how many envelopes the fork carries beyond the fence point; the fork is plain JSONL, so copy-paste salvage works forever. Auto-reconcile was rejected for the same reason pull is one-way: bidirectional reconciliation is the split-brain swamp the event-sourced design exists to avoid.

**Status: design pinned, build unscheduled.** Nothing here changes what ships now. The ticket graduates to implementation when ADR-0033's tripwire fires — the offline-host demand signal opening hosted authority before this is built. When it does, there is no design left to re-litigate.

**Consequences — interactions single-host surfaces must record** (the cheap doors this keeps open):

- The pipe loop's retry-forever posture is now a named hazard: it must learn the terminal-fencing refusal before handoff ships, and until then must not weld "refuse means stop" shut.
- Last-registrar-wins supersession is a named hazard: same-identity supersede stays correct only while ownership cannot change behind the registry's back.
- Fold checkpoint rebuild on attach already starts a fresh fold per registration, which is compatible with claim transfer; no comparison against a previous host's seq exists yet, and the epoch rule defines what that comparison must become.
- Core gains exactly one new event type; old readers skip it silently (fold posture), so shipping the vocabulary early is safe even before anything calls it.

**Revisit triggers:** the transfer event's payload shape may grow (e.g. explicit reason codes) when implementation lands; the any-seat-holder rule narrows only via ADR naming an incident; orphaned-event salvage grows tooling only if a real table actually loses writes to a partition.
