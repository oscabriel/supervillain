# v0 macOS codesigning is ad-hoc

The product definition pins "curl installer + checksums + macOS codesign from day one" for the CLI artifact without naming the signing identity. v0 signs with the **ad-hoc identity** (`codesign --force --sign -` in the release workflow, verified with `--verify --strict`): arm64 macOS refuses to run unsigned binaries at all, and `bun build --compile` mutates the executable after link, so an explicit re-sign is required for the binary to run on players' machines. Ad-hoc satisfies that hard requirement with zero secrets in CI. What it does not buy is Gatekeeper provenance: a browser-downloaded (quarantined) binary still shows the unidentified-developer prompt. The curl installer path — the documented v0 door — never sets the quarantine attribute, so the shipped flow is unaffected.

**Revisit trigger:** a real cohort of macOS GMs acquiring the binary outside the curl installer (browser downloads, future brew tap), or an Apple Developer Program membership landing for other reasons — then move to Developer ID signing + notarization as a release-workflow secret, which slots into the existing codesign step without restructuring the pipeline.
