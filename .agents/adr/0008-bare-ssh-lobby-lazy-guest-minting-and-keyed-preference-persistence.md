# Bare-ssh lobby: live gateway TUI, lazy guest minting, and keyed preference persistence

Resolved 2026-07-22, grilling of [#44](https://github.com/oscabriel/supervillain/issues/44). The definition routes players via `ssh <room>@supervillain.app` and never specified bare `ssh supervillain.app` or the unknown-room case. Prior art: terminal.shop's bare-address storefront (`.agents/research/terminal-shop-architecture.md`, `terminal-shop-and-wish-precedent.md`) applied as spook-reduction — let people touch the product before installing anything.

**Decision: bare ssh lands in a live, interactive lobby TUI — a held session, not a banner-and-drop.** Gateway-side chrome: splash (pixel-glyph wordmark per [ADR-0007](./0007-pixel-glyph-rendering-tier.md) — the lobby is that identity's prime real estate), interactive join-a-room, a "Become a GM" informational screen (install pitch: your machine, your files, free forever — the gateway **cannot** create rooms; room authority lives on the GM's machine and gateway-hosted rooms are the v3 paid tier), and a settings screen. No game imports, no new deployable. The lobby inherits the gateway hardening checklist (idle/max timeouts, per-IP rate limiting) immediately rather than eventually.

**Decision: two surfaces, split.** The want "all CLI capabilities via a TUI, no memorized commands" is real but lives on the GM's machine, not the gateway — a **local launcher TUI** over the same pinned verbs (create/join/publish). That is a genuine definition gap, surfaced as its own ticket rather than decided inside #44. #44 owns the gateway lobby only.

**Decision: guests are pre-identity in the lobby — `guest:` mints lazily at first room entry.** Actors exist to stamp envelopes; the lobby writes to no log. [ADR-0003](./0003-gateway-registration-trusted-stamping-and-guest-actors.md)'s "minted per SSH session" was written for `ssh <room>@` where session = room entry; bare ssh decouples those. Clarification, not change: one `guest:<12 hex>` actor per SSH session, minted at the first room entry through the lobby and reused across room hops; the upgrade box renders at that same threshold — before the guest sits down, exactly ADR-0003's placement. Keyed connections resolve identity at connect (the key _is_ the identity; nothing is minted) because preference lookup needs it.

**Decision: presentation preferences persist for keyed users; guests stay session-local.** The gateway gains a second durable table (bun:sqlite, next to the room registry): resolved identity → presentation prefs (render tier, theme-ish toggles — never game or campaign state). Keyed by **resolved** identity so linked keys ([ADR-0005](./0005-key-linking-backend-registry-gateway-conduit-and-in-log-linking-events.md)) share prefs. This fires ADR-0007's "preference persistence" revisit trigger for the gateway surface and re-pins the glossary's "stateless doorway": **stateless means no game state** — registry, host key, and presentation prefs are durable; game state, campaign data, and authority never are. Guest amnesia is deliberate (ADR-0003: continuity means bringing a key) and sharpens the upgrade pitch: bring a key and it remembers you.

**Decision: unknown and offline rooms land in the lobby chrome, not a disconnect.** `ssh <name>@` where the name is unregistered ("no such table") or registered-but-unreachable ("table isn't live right now" — an everyday event in a GM-hosted product) renders an inline notice with the typed name preserved, full lobby underneath. The name-enumeration disclosure (distinct copy confirms which names exist) is accepted knowingly: rate limiting mitigates, and names were never capability secrets — security lives in the host's authority. Floor: if the TUI itself fails, a plain-text one-liner before disconnect.

**Decision: staged shipping.** v0: lobby chrome, join, become-a-GM screen, session-local settings, error paths, pixel-glyph wordmark — everything stateless, serviceable copy. v1: the preferences store (arrives with ADR-0005 identity-resolution machinery it needs anyway) and a coordinated copy pass — recorded as a named line item on [#37](https://github.com/oscabriel/supervillain/issues/37) so the polish cannot silently slip.

**Decision: the deadpan register fires in exactly two places, one line each** — the splash tagline and the offline-table beat (functionally a marketing headline and an empty state, both already licensed emotional beats in the definition's restraint rule). Everything else — menus, settings, become-a-GM body copy, the no-such-table error — stays structural and dry. Every screen must work with its tagline deleted. Phrasing candidates were handed to #37 as input, not decree.

**Consequences:** the gateway gains a lobby chrome surface and a prefs table with a migration story (every future pref is a schema question on a freely-redeployed service); the lobby session carries two guest identity states (no-actor / actor-minted); a keyed user's prefs persist while the same human arriving keyless gets amnesia (accepted support-question fuel); a new sibling ticket exists for the local launcher TUI.

**Revisit triggers:** the lobby gaining any guest-visible feature that writes state (would force the minting question back open); preference persistence arriving product-wide (the lobby's store should merge into it, not stay bespoke); lobby squatting/abuse outgrowing the hardening checklist (concurrent-connection cap becomes real work); the local-launcher ticket landing on a design that wants shared lobby components (keep the chrome shareable).

**Amended 2026-07-25, after [#58](https://github.com/oscabriel/supervillain/issues/58)/[#60](https://github.com/oscabriel/supervillain/issues/60)/[#67](https://github.com/oscabriel/supervillain/issues/67) — the notice vocabulary grows two kinds, and the bare-arrival case is named.** (1) The inline-notice vocabulary is now **four** kinds: `unknown-room`, `offline-room`, **`full-room`** (a Room at its session cap refuses honestly — landed with #60's capacity work), and **`dropped-behind`** (a seat dropped for exhausting its output budget lands back in the lobby with an honest notice, not a bare farewell on a dying channel — replaces #58's interim plain-text `SEAT_BEHIND_MESSAGE`). Copy for both new kinds belongs to [#37](https://github.com/oscabriel/supervillain/issues/37)'s pass. (2) **Bare arrival is a named case the copy must cover, not a state the code can detect.** An SSH client with no explicit user sends the local account name, so bare `ssh <gateway>` is indistinguishable on the wire from a typed room name — and heuristics (e.g. "no key offered") misclassify, since real clients auto-offer `~/.ssh` keys. The mechanism stands as this ADR designed it (any unregistered name → lobby splash with an inline notice); what changes is that the unknown-room notice's copy must read as a welcome-with-a-footnote in the lobby's voice — it is most visitors' first screen — and its severity presentation may be demoted from danger accordingly. #37 owns the wording. (3) The **render-tier toggle leaves the settings screen until a second tier exists** — [ADR-0007](./0007-pixel-glyph-rendering-tier.md)'s pixel tier is not in source and [#50](https://github.com/oscabriel/supervillain/issues/50) may yet strike it; an inert control teaches users the settings screen lies. (4) The hardening checklist's numbers as shipped by #67 (5 min idle, 30 min max hold, 30 connections/IP/min, all environment-settable) are ratified as **floors on unauthenticated held sessions, not capacity policy** — they are not R9-gated ([ADR-0012](./0012-outbound-only-hybrid-drop-iroh-host-dials-out.md) NQ-10 governs capacity caps, and [#60](https://github.com/oscabriel/supervillain/issues/60)'s benchmark kept these floors as-is).

**Amended 2026-07-30, after [#90](https://github.com/oscabriel/supervillain/issues/90) — the enumerated screen set gains `whoami`.** The Lobby's screens are now splash, join, become-a-GM, **whoami**, and settings. The `whoami` screen is reachable from the splash menu and reports what the Door session resolved — identity (`guest` or `keyed`), the fingerprint of the key that won authentication, and the other key fingerprints linked to that identity — in the keys-not-people vocabulary #90 pins (we recognize keys, never claim to recognize people). It hosts the "link this key too" repair beside the diagnosis: a keyed session redeems an existing [ADR-0005](./0005-key-linking-backend-registry-gateway-conduit-and-in-log-linking-events.md) device-link code against exactly the SSH-matched key — new Lobby reachability over existing linking machinery, not new machinery. Per [ADR-0019](./0019-one-vocabulary-doorways-by-authority-command-grammar-and-flag-policy.md)'s doorway rule the same answer ships as `supervillain whoami [--json]`, with identical fields on both doorways. The screen is structural and dry; no new deadpan line. Its copy joins [#37](https://github.com/oscabriel/supervillain/issues/37)'s pass with the rest of the lobby's.

**Amended 2026-07-30, after [#88](https://github.com/oscabriel/supervillain/issues/88) — rate limiting gains a second axis: per-IP before identity resolves, per-identity after.** The hardening checklist's "per-IP rate limiting" was written for pre-identity arrivals, where an IP is all a Guest presents — that axis stands, and its shipped floors (30 connections/IP/min, amendment (4) above) are untouched. Post-identity it is the wrong key: one abusive key behind a shared NAT punishes a whole table, and a player on a phone hotspot gets throttled by a stranger. Once identity resolves, rate budgets attach to the **resolved identity — the linked-key equivalence class of [ADR-0005](./0005-key-linking-backend-registry-gateway-conduit-and-in-log-linking-events.md)/[ADR-0013](./0013-server-data-layer-gateway-owned-identity-and-two-stores.md), never the individual key**. This diverges deliberately from the exe.dev precedent (per-key budgets to isolate independent workloads — `.agents/research/exe-dev-precedent.md` §9.2): our identity is a linked key set, so a per-key budget would hand a linked set N× the allowance — the same reasoning that keys preference persistence on resolved identity above. On the record: (a) this axis is load-bearing, not hygiene — this ADR leans on rate limiting as the mitigation for the knowingly-accepted room-name enumeration; (b) any multi-key guidance we publish must ship the `IdentitiesOnly` pinning stanza in the same breath, because per-key budgets are exactly what pushed exe.dev's docs toward a-key-per-purpose — the practice that manufactures the multi-key misresolution trap #90's `whoami` screen exists to repair. Per-identity numbers remain floors-not-capacity, environment-settable like the rest of the checklist; [ADR-0012](./0012-outbound-only-hybrid-drop-iroh-host-dials-out.md) NQ-10 still governs any capacity claim.

**Amended 2026-08-04 by [ADR-0030](./0030-closed-pane-frames-tab-traversal-side-rails-and-contextual-key-help.md) — the Lobby gets a distinct open visual baseline and the prefs carve-out gains three instances.** The Lobby is a horizontally centered upper-third composition in a large quiet field: pixel wordmark first, open left-aligned content beneath, closed light boxes only around typed fields, `!`-marked arrival callouts, and a screen-contextual terminal-bottom hint bar. It does not inherit the Table's boxed Pane grid. The keyed presentation-prefs table now also carries the opt-in focus marker plus independent Feed-Rail and Sidebar-Rail choices; as everywhere in this ADR, keyed choices follow resolved identity and Guests retain them only for the Door session. A deeper Lobby art pass remains follow-up polish.
