# Packaged-data provenance: repo-wide convention, per-package manifests, honest CI split

Resolved 2026-07-22, in-session grilling of [#48](https://github.com/oscabriel/supervillain/issues/48), surfaced by the 2026-07-21 deep review ([#25](https://github.com/oscabriel/supervillain/issues/25) acceptance re-verification): the packaged Draw Steel template ships named content (Human, Tactician, Focus, Sword and Board) with no per-datum provenance, so "sourced solely from the license's enumerated documents" was not independently verifiable from the repository. [ADR-0007](./0007-pixel-glyph-rendering-tier.md) had already invented a provenance header for the glyph atlas; this ADR standardizes that shape for all packaged data.

**Decision: the convention is repo-wide, not Draw Steel–specific.** Every third-party datum baked into any package — game-module `content` data, the glyph atlas, any future font/art/dataset — records provenance in one shared field vocabulary. The Draw Steel case is the strictest instance: its citations must name one of the license's enumerated documents (per `.agents/wayfinder/assets/draw-steel-license.md`, the license covers a document _list_, not one undifferentiated corpus).

**Decision: one vocabulary, two encodings, by the nature of the file.** _Generated_ data files keep the ADR-0007 generator-written comment header (unchanged, still binding — self-maintaining because the bake script writes it). _Hand-authored_ packaged data is covered by a per-package machine-readable manifest, `provenance.json`, living next to the data it describes. Per-package, not repo-root: the manifest sits beside what it cites and avoids a contended shared file.

**Decision: seven fields, work-level citation.** Each record carries `data` (the facts sourced), `work` (source work's title), `version`, `author`, `license` (name + URL), `sourceUrl`, `accessed` (ISO date); optional free-text `notes` for finer locators. No page/section requirement — the license boundary is the document list, not pages; requiring locators would buy audit speed with maintenance rot across document revisions (backer packets → final books).

**Decision: manifest entries are sourcing groups, and every fact is individually named.** An entry's `data` is a list of `{ value, note? }` items sharing the entry's other six fields — per-datum resolution without seven-fields-times-ten duplication. Each `value` must occur verbatim in the package source (this is what forward coverage checks). Entries carry a `kind`: `game-data` (the `work` must be one of the six enumerated documents) or `license-text` (verbatim license-mandated text, e.g. the independence notice, cited to the Creator License itself).

**Decision: CI checks the mechanical three; reverse coverage is a stated review obligation.** Ordinary `bun test`s in the owning packages check (1) **schema validity** — the manifest parses, fields are present, `game-data` entries cite an enumerated document; (2) **forward coverage** — every `data` value occurs in the package source, catching stale entries and typos; (3) **header presence** — generated data files carry the provenance header. **Reverse coverage — that every licensed datum in the code appears in the manifest — is not mechanically decidable** (no tool distinguishes "Tactician" from UI wording we chose) and is explicitly a review obligation. #25's licensing criterion is therefore restated honestly: _every claimed datum is verifiably cited; completeness of claims is reviewed, not computed._

**Decision: the convention ships with its first conforming instance.** `packages/games/draw-steel/provenance.json` covers the packaged Draw Steel facts — the five characteristic display names, the tier labels, Human / Tactician / Focus / Sword and Board, and the template starting values (stamina 21, recoveries 8) — all attested in-session as sourced from _Draw Steel: Heroes_ — plus a `license-text` entry for the independence notice. `panelTitle: "Initiative"` and the side labels "Enemies"/"Heroes" are our UI wording, excluded by exactly the review judgment this convention names. The glyph atlas needs nothing: ADR-0007's header already conforms.

**Consequences:** `packages/games/draw-steel` gains `provenance.json` and `test/provenance.test.ts`; the product definition's licensing criterion gains a dated correction pointing here; any future package baking third-party data owes either a generated header or a manifest plus the two-check test; [#36](https://github.com/oscabriel/supervillain/issues/36) (repo publicization) independently adopted "Draw Steel provenance manifest present and passing per ADR-0011" as a publicization precondition — their decision, now discharged by this ADR's first conforming instance.

**Revisit triggers:** packaged data grows past the point where a hand-reviewed reverse-coverage obligation is credible (→ consider the string-literal allowlist lint rejected here as disproportionate); a second game module arrives (its license may demand different fields — the vocabulary may need a per-license extension point); MCDM revises the enumerated-document list (the hardcoded six-title check must track the license page).
