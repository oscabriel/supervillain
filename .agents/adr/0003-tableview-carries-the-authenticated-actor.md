# TableView carries the authenticated actor, and the panel-input contract lands

Issue #10 (the thin Draw Steel module) surfaces the first authority rules that depend on _who_ issued a command — start/end encounter, roster edits, and character intake are GM-only. `decide(state, command, table)` has no actor parameter, and trusting an actor field inside the command payload would undo ADR-0002, which pinned the connection as the authenticator: `serveRoomStore` rejects submissions whose claimed actor differs from the connection's key. The seam doc already defines `TableView` as "a read-only snapshot value captured at command time, exposing the narrow core facts `decide` may read (seats, who holds the GM seat)" and names it the licensed churn point.

**Decision: `TableView` gains `readonly actor: string` — the authenticated ed25519 key (lowercase hex) of the perspective the snapshot is captured for.** In `decide`, that is the connection-authenticated issuer of the command being decided (stamped by the host from the same value ADR-0002 verifies at the wire). In a panel's `GamePanelInput`, it is the viewing player's own actor, so a panel can answer "am I the GM?" without a side channel. One field, one meaning: whose behalf this snapshot serves. Widening `decide`'s signature with a fourth parameter was rejected — the actor is a core fact captured at command time, which is exactly what `TableView` is for, and the churn point is licensed where a new parameter is not.

Alongside it, #10 implements the seam's already-specified panel-input contract (rider 3: core owns focus routing; a focused panel receives input; its only output is `dispatch`): `GamePanel` gains an optional `onKey`, `render` returns `readonly FeedLine[]` so trackers can be multi-row, and `GameView` gains optional `notices` (how a module puts its license-mandated text on core chrome without the gateway importing `content`). Those are recorded as a dated correction in `game-module-seam.md`; this ADR exists for the actor decision, which changes what `decide` can enforce.

**Revisit trigger:** character↔seat bindings (v1 named churn on `TableView`) should subsume any temptation to add per-seat facts to commands; if a game needs finer-grained authority than "GM or seated actor," that is `TableView` growth, not payload trust.
