# The web stack: TanStack Start pages, a mounted Hono API, one Bun process on the VPS

Resolved on [Web framework pick (#31)](https://github.com/oscabriel/supervillain/issues/31), 2026-07-28. The empirical evidence is the completed spike matrix [#43](https://github.com/oscabriel/supervillain/issues/43) (`.agents/research/43-framework-spike-matrix.md`), which installed, production-built, and booted all four finalists from `.agents/research/31-web-framework-pick.md` under Bun 1.3.13 on linux-x64 with the repo's pinned TS 7.0.2. The decided constraints honored: SSR pages (marketing, docs, Artifact pages at capability URLs), push-ingest snapshot endpoints, publish-time OG generation, a passkey-ready empty auth slot, Bun-workspace citizenship under TS7 composite builds, and the one-box hosting posture from [#30](https://github.com/oscabriel/supervillain/issues/30) with [ADR-0013](./0013-server-data-layer-gateway-owned-identity-and-two-stores.md)'s data layer.

**Decision: TanStack Start is the page framework for `apps/web`.** The spike proved the two things the research report flagged as its unknowns: the official Bun deployment path (via the nitro/vite plugin, `preset: 'bun'`) boots, serves SSR dynamic routes, ingests POSTs, and drains SIGTERM out of the box; and the TS7 composite proof passes with real declaration emit, including the generated route tree. Spike-verified versions: `@tanstack/react-start` 1.168.32, `@tanstack/react-router` 1.170.18. Accepted concessions, stated plainly: `skipLibCheck: true` is required — an upstream d.ts defect in `@tanstack/router-core` (`MakeRouteMatch.__beforeLoadContext` TS2339), not a defect in our code — so the pick carries a pin-and-watch note rather than a strict-clean lib check; the release cadence is intense, so upgrades are deliberate, not automatic; experimental RSC is excluded — it adds no launch value. Rejections from the spike, not from taste: **Nuxt 4** is disqualified in this repo's build discipline (generated tsconfigs are `noEmit`/non-composite, root `tsc -b` is permanently dirty, 836 transitive deps, and its first-party bun preset silently drops in-flight requests on SIGTERM without a hand-written plugin). **SvelteKit** passed everything clean and loses only on `svelte-adapter-bun` — a one-maintainer community package with a 2023→2025 release gap sitting on the core hosting posture; it is the named fallback if TanStack's cadence or the `skipLibCheck` concession becomes toxic. **Hono-alone** would have made the team hand-build head/meta, docs pipeline, assets, and island conventions — real product infrastructure the launch surface shouldn't fund.

**Decision: Hono is the backend surface — mounted inside the TanStack server, not a separate deployable.** A Hono app (spike-verified 4.12.31) owns the machine-facing routes under `/api/*`: snapshot ingest, revoke, the future Better Auth catch-all, and OG regeneration. Hono is a Fetch handler, so it mounts in TanStack Start's server entry directly; the product gets Hono's explicit typed routing for exactly the surface the research praised it for, without a third process. The alternative — a separate Hono process with Caddy splitting `/api/*` — was rejected: a third systemd unit and a third deployable buying no isolation, when ADR-0013's identity interface already draws the seam in code. The definition's "two deployables, one monorepo" (gateway + web) survives unbent. Pages stay TanStack's: the Artifact page at `/a/:capability` is SSR with loader-driven 404s, per the spike shape.

**Decision: the web deployable stays on the VPS; serverless hosting is considered and declined.** The question was asked directly (Cloudflare/Netlify for `apps/web` while the gateway keeps the VPS) and the answer is #30's refuted split posture, still refuted: the apex serves two protocols — `ssh <room>@supervillain.app` needs TCP 22 answered at the same name that answers 443 — so pointing apex DNS at an edge platform kills the SSH pitch or forces Spectrum-class plan-gated TCP proxying plus the origin box anyway. Beneath that, ADR-0013's data layer is co-location-shaped by decision: snapshots are files on disk under `/var/lib/supervillain/`, the store is `bun:sqlite`, Litestream replicates the tree, and the backend's "remote" identity implementation is a local call to the gateway on the same box. Serverless would trade all of that for a second platform, a second data store, and a real cross-network identity protocol — to accelerate a workload that is one indexed SQLite lookup per capability read and publish-time-generated OG images served as static files. The recorded escape hatch stands unchanged: the apex-for-SSH / `www.`-for-web split remains the named fallback if the web surface ever genuinely wants a CDN. "One long-lived Bun process" is thereby a consequence of the posture, not doctrine: one box, one web systemd unit behind Caddy, beside the gateway unit.

**Decision: publish is unblocked on the consent axis — the owner declares the consent/permission questions non-issues.** The strategy review had flagged [#87](https://github.com/oscabriel/supervillain/issues/87)'s items (b) per-character consent flags and (c) minors/age-gating as definition bugs gating publish implementation. The owner's call, recorded here rather than made silently: these are non-issues for this product — no per-character consent gate, no age-gating machinery; publish authority rests with the GM. #87's remaining items — the propose-vs-run verb list, the operator's takedown powers, and the token-handle pre-commitment — stay open as ordinary design questions on their own merits, no longer framed as publish blockers.

## Consequences

- `apps/web` arrives as one workspace app: TanStack Start with `composite: true` off the config base, the Hono app mounted in its server entry, importing **zero game packages** (ADR-0009: published snapshots are self-describing; the model+content ceiling stands as the never-exceeded bound).
- The data layer is already decided and unchanged: Drizzle over `bun:sqlite` in the web backend, the shared `PRAGMA user_version` migration runner, snapshot files on disk (ADR-0013). The spike adds one hard fact: **better-sqlite3 hard-crashes Bun** (NAPI fatal, process death, not catchable) — Better Auth recipes defaulting to it must be re-pathed through `bun:sqlite`/Drizzle when the auth slot is filled.
- OG generation is Satori + `@resvg/resvg-js`, at Publish time, PNG persisted beside the snapshot, endpoint retained for regeneration (~100 ms/render, deterministic, spike-verified under Bun).
- `product-definition.md`'s "v1 web framework pick" churn row is cashed; it and `monorepo-stack.md`'s web-slot bullets gain dated corrections pointing here. The bts-graft option for scaffolding `apps/web` is dead — the app is hand-rolled against TanStack's own templates.
- #31 closes with the pick; #43 closes as complete (its report was already the evidence); #87 gets the consent scope-cut recorded.

## Revisit triggers

SvelteKit is the fallback, promoted only if TanStack's release cadence or the `skipLibCheck` concession produces real recurring cost. The `www.` split opens only on measured CDN demand for the web surface. linux-arm64 was never executed (package-existence only) — re-run the spike's runtime matrix before any move to an arm64 box. Serverless for `apps/web` returns only if the apex two-protocol constraint itself dissolves (it is the load-bearing reason). The mounted-Hono shape is revisited only if the API surface develops needs the page server cannot host (long-lived connections, divergent scaling) — at which point the split is a Caddy route and a second unit, not a rewrite.
