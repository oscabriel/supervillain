# Bitmap map tier: kitty graphics protocol, probe-gated, first-party where supported

Resolved 2026-08-20, in-session ratification, following the gloomberb reference research (`.agents/research/gloomberb-kitty-graphics-reference.md`, baseline `e55bf24`, amendments re-verified @ `8a6074e`) and the #38 FrameBuffer research. The product stance driving it: the battle map should be first-party pixel graphics for players whose setups support it, with the existing fallbacks otherwise. This **amends [ADR-0007](./0007-pixel-glyph-rendering-tier.md)'s "no image protocols" line and adds a scoped exception to its no-capability-detection stance.** Everything else in ADR-0007 and [ADR-0021](./0021-mekmode-atlas-octant-packing-and-4x3-tiles.md) stands: the pixel-glyph tier, its atlas, its geometry, the text tier as the source format, and "this changes nothing below the renderer."

**Decision: the map surface gains a third render tier — bitmap mode, via the kitty graphics protocol.** The ladder is bitmap → pixel-glyph → text. Bitmap mode transmits real RGBA rasters to the player's terminal as APC escape sequences over the existing ssh Door — no client install beyond a supporting terminal (as of 2026-08: Kitty, Ghostty, WezTerm, Konsole, iTerm2 3.6+, Warp, Zellij-over-a-supporter; not Alacritty, Windows Terminal, GNOME Terminal, foot, xterm, Terminal.app, or any released tmux). The protocol is bytes on stdout, so it traverses ssh unchanged — the fact that makes this viable at all. Gloomberb (MIT) is the reference implementation for the emitter, double-buffered transmit, and strip re-encode; OpenTUI at the pinned clone already probes and exposes `capabilities.kitty_graphics`, and its private `writeOut` is reachable by cast-and-guard without patching.

**Decision: bitmap mode is gated by a real probe; ADR-0007's no-detection stance stands for the tiers below.** ADR-0007 rejected detection because quadrant/octant font coverage has no probe — that argument is untouched and still governs the pixel-glyph tier. The kitty protocol is epistemically different: a query/response handshake anchored on primary device attributes (`\x1b[c`), where "DA answered, graphics didn't" is a definitive no at any link latency. At connect: probe; supported → bitmap is the default tier; unsupported → pixel-glyph default, exactly as ADR-0007 pinned. The `t` key cycles the *available* tiers (text and pixel-glyph always; bitmap only when probed). A failed or absent probe is silent — no nag, no error. Text mode remains a per-session opt-in in every case, never a default.

**Decision: multiplexers force bitmap off, as a dated policy.** A multiplexer that doesn't speak the protocol swallows the probe and would print image payloads as literal base64 into the pane — the one failure mode that is worse than tofu. Detection mirrors gloomberb's: renderer-reported multiplexer wins; `$TMUX` / `TERM_PROGRAM` / `TERM` consulted otherwise. This is dated: tmux merged kitty graphics 2026-03-05 (post-3.6, unreleased) and Zellij shipped it 2026-07; the reopening trigger is below, stated against those baselines.

**Decision: v1 bitmap content is the same map, not a new authoring surface.** Bitmap mode renders the same map model — map file, legend, MEKMODE atlas vocabulary, tokens, theme-token styling — as true pixels. One tile remains 4×3 terminal cells, so viewport math, layout presets, and the demotion ladder are identical between pixel-glyph and bitmap; the tier changes rasterization only. (The 8×12 MEKMODE glyph at 2:3 aspect scales exactly onto a 4×3-cell region at common cell metrics; actual scale derives from the terminal's reported cell pixel size, nearest-neighbor to stay crisp.) On a supporting terminal, bitmap mode also sidesteps the octant tier's Unicode-16 tofu risk entirely. GM-supplied map art — bitmaps decoupled from the one-character-per-cell map file — is explicitly **out of scope**: it reopens ADR-0006's map-capture contract and the glossary's map-file term, which is definition work, not renderer work.

**Decision: the ANSI-16 contract gains one carve-out — the interior of the bitmap payload.** Pixels inside a transmitted image are truecolor RGBA; every terminal cell outside the image, and both lower tiers, keep the byte-level exact-ANSI-16 guarantee unchanged. ADR-0006's "richer palette + double-width cells" churn row is still not fired: nothing about cells changes.

**Decision: placement is placeholders-first.** Unicode placeholders (`U+10EEEE` cells whose fg color carries the image ID) are the committed mechanism: they live *inside* the cell grid and ride OpenTUI's existing diffing, z-order, and clipping for free — no occlusion manager, no occluder-rect registration by floating Table elements — and they are the mechanism tmux-dev and Zellij use, so the tier is multiplexer-proof the day those releases land. The accepted price: the probe gains a placeholder-support condition and the supported list shrinks (Konsole lacks placeholders; iTerm2 unverified — the prototype checks it). Classic placements (`a=p`) plus a gloomberb-style occlusion manager are the recorded fallback plan, adopted only if the prototype shows placeholders failing on real terminals; two placement sub-tiers shipping together is rejected as over-engineering. The prototype validates this decision rather than making it.

**Decision: every number in this tier is a placeholder until a benchmarks-dir run exists (ADR-0012, NQ-10).** That includes the probe's no-answer timeout guard, deflate level (gloomberb's level 3 is tuned for local-pty CPU; our constraint is ssh bandwidth, which inverts it), chunk size, and the full-map transmit budget (envelope estimate: a full map region is a few hundred KB deflated+base64 — fine as an occasional transmit, unacceptable per-frame; token moves must be strip re-encodes in the kilobytes). The benchmark runs over a real ssh link, not a local pty.

**Commitment level: v1 target, slippable by construction — same clause as ADR-0007.** The two lower tiers are complete and identical in data and interaction; "bitmap mode slips out of v1" is a one-line churn entry. The direction is decided now on source-verified mechanics; the prototype validates geometry, placement mechanism, and cost — not whether.

**Consequences:** the glossary's **Pixel-glyph mode / Text mode** entry becomes three tiers and gains **Bitmap mode** (avoid: graphics mode, image mode, kitty mode); `packages/table/DESIGN.md` § Render tiers gains the bitmap rung and its probe note; the demotion ladder's tier column stays two-valued for viewport math (bitmap costs 4×3 like pixel-glyph); ADR-0007 gains an amendment header; the repo gains a prototype/benchmark issue ([#134](https://github.com/oscabriel/supervillain/issues/134): placement mechanism, probe-over-Door verification, ssh transmit benchmark, cell-pixel-size handling); the render side gains an emitter package-or-module whose seam placement (core chrome vs beside the atlas) the prototype issue resolves against the dependency lattice.

**Revisit triggers:** a released tmux carrying kitty graphics (`cf6cbe4`) reaches mainstream distros (→ reopen the multiplexer hard-off); the prototype shows placeholders failing on real terminals (→ the fallback plan lands: classic placements plus the occlusion manager, re-estimate v1 fit); that fallback also fails (→ tier slips, churn entry); iTerm2/Konsole placeholder support changes (→ recompute the supported list); real demand for GM-supplied map art (→ definition session on ADR-0006 and the map-file term, not an amendment here); OpenTUI ships a public image API or raw-write channel (→ delete the cast-and-guard).
