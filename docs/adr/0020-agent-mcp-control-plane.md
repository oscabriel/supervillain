# Agents sit at the table over MCP, as a GM or a player, through the same intake as a typed line

## Decision

An AI agent joins a live table as an MCP server session (`apps/supervillain/src/mcp/`), built on Effect's own `effect/ai/McpServer` with protocols `2025-11-25`, `2025-06-18`, `2025-03-26` and `2024-11-05`, and no new dependency. Each session builds its own `McpServer.layerStdio` inside its scope, over a `Stdio` made from the session's byte stream (`duplexStdio`), so one session's actor and role never reach another's tools. There are three ways in:

- **The GM's own machine:** an open table (`supervillain host`, headless or not; never a sandbox) listens on `<campaign>/mcp.sock`, or, when the staging path below would pass 100 bytes, on `${XDG_RUNTIME_DIR or the temp dir}/supervillain-<uid>/<sha256 of the folder, 16 hex>.sock`. That fallback folder is made `0700`, then `lstat`ed: the table and `supervillain mcp` both refuse it when it is a symlink or not a folder, belongs to another user, or has any group or other permission bit. The table listens on a staging socket inside a fresh `0700` folder, `.mcp.<pid>` beside the final socket, `chmod`s it `0600`, renames it into place and removes the staging folder, so no other user can reach it at any mode. A leftover socket is removed only when connecting to it is refused (`ECONNREFUSED`) and it is a socket; any other failure, like `EACCES`, leaves it alone and names it. A live one fails the second table, and the socket is unlinked on close. When the socket can't open, the table still opens and prints `agents on this machine: unavailable (<why>)`. Every connection is the GM. `supervillain mcp [campaign-dir]` pipes stdin and stdout to it, writing nothing but MCP on stdout and failing on stderr when no table is open there.
- **Any player's own `ssh`:** the SSH subsystem `mcp-1@supervillain.sh`, on the table's server directly or through the relay (`ssh -s <handle>/<table>@<relay> mcp-1@supervillain.sh`, or the bare `<table>` a returning player's key resolves through `knows-1`). `ServeOptions.subsystems` holds actor-bearing subsystems: a relayed connection may open one only with `SV_ACTOR` set, after the relay-only `relaySubsystems` (`knows-1`), which players can never open. The relay's player-facing server routes `mcp-1` like a seat without the lobby, says so on stderr when a shorthand names no table or several, and says "This table's host is too old to take agents." when the host refuses the subsystem. `patches/ssh2@1.17.0.patch` gives `Client.subsys(name, { env }, cb)` the environment `exec` and `shell` already send, so the relay can name the player.
- **A remote GM:** a key fingerprint listed in `<campaign>/gm_keys` (one `SHA256:` per line, at most 16 KiB of UTF-8) opens `mcp-1` as the GM; any other key opens it as itself. The file is `lstat`ed and ignored, with one warning until its problem changes, when it is a symlink or not a plain file, belongs to another user, or is group- or world-writable. Shell seats are unchanged.

A session refuses a `guest:` actor (an agent's identity must outlive a reconnect) and, for a player, an actor `isMember` rejects. It enters `Presence` like a seat, so `/play` and `Seating` see the agent, and it closes the moment the player stops being a member (`/kick`, a `/door knock` that leaves them out).

Every command in `commandsFor(ruleset)` is a tool `cmd_<type>`, the GM-only ones only for the GM (`decide` still enforces `gmOnly` and membership). Its JSON Schema comes from the command's own `Domain.Command` class (`COMMAND_CLASSES`) with `_tag` and that command's host-fact keys (`HOST_FACT_KEYS`: sheets, grids, seats, cast, `whose`, set.world characters, `playerActor`, cards, and `admit`'s `member`, `name` and `by`) removed, and `additionalProperties: false`. `commandFromInput` refuses any other key, and any command outside the table's ruleset (a `pf-*` step in a Draw Steel `batch_commands`), so a forged host fact never reaches `intake`; the command then goes through the same `intake`, rate limit and `Table.send` as a typed line. Everyone also gets `send_line`, `get_table_state`, `wait_for_change` (at most 30 s) and `help`; the GM adds `batch_commands` (up to 32 steps, each logged as its own undo batch), `reload_content`, `validate_content`, `deny_knock`, `create_invite`, and `set_auto_foes` at a set.world table. A refusal is a tool result with `isError: true`, never a protocol error.

A player's session is bounded before anything is parsed: every tool call and resource read takes a token from a table-wide `AgentLimits` limiter keyed by the seat's rate key (burst 20, 2 a second, so a second session for the same key shares it), at most 4 run at once, and at most one `wait_for_change` is parked; past any bound the call is refused at once, with `isError: true` for a tool. `send_line` takes at most 2,048 characters, `deny_knock`'s `who` 128, `help`'s `topic` and a batch step's `type` 64, and resource parameters 128 (Effect's URI router already stops at 100). The GM's sessions are not bounded.

A player's state (`get_table_state`, `supervillain://table/state`) is only `{ seq, ruleset, myName, present, party, stage, band, map, feed }`, the projections a seat already draws. `supervillain://sheet/{who}` reads a party member's sheet, and `supervillain://codex/{key}` only a card on the stage. A player's `send_line "/sheet <who>"` passes the same `canReadSheet` check and is refused with the same words ("No one in the party is called …"), so a typed line is no way around the resource; a person at a seat still reads any creature's sheet with `/sheet`. The GM's state adds the prep panel, the real state, recent envelopes, the catalog, GM notes, content problems and who is knocking; the GM alone reads `supervillain://campaign/files`, `supervillain://campaign/{kind}/{id}` (resolved through the content index, never a path built from the request) and `supervillain://schema/{kind}`.

## Why

- An agent is one more seat at the table. Going through `intake` and `Table.send` keeps the log, replay, undo and refusals exactly what they are for a person typing.
- The tool schemas are the commands' own classes, so a new command or field is a new tool argument with nothing to keep in step by hand; dropping the host-fact keys is what keeps "the host fills this" true when the caller is a program that can type anything.
- A local socket needs nothing but the folder, and the SSH subsystem needs nothing but the `ssh` and key a player already joins with: no install, no account, and the same identity rule as a seat (ASSESSMENT Q9).
- A fresh `McpServer` per session is the only way to give one connection a GM's tools and the next a player's: the layer memoizes its registry.

## What breaks if you change this

- Sharing one `McpServer` across sessions hands a player the GM's tools or acts as the wrong actor.
- Letting a tool take a host-fact key lets an agent invent a sheet, a map, a card, a seat or an admission the host never read.
- Accepting `mcp-1` on a relayed connection without `SV_ACTOR`, or `knows-1` from players, lets anyone speak as the relay.
- Answering a refusal with a JSON-RPC error hides it from the model, which then retries blind.
- Listening before the socket is `0600` in place outside a private folder, trusting a symlinked or loose socket folder, unlinking a socket on any error but `ECONNREFUSED`, or trusting a group-writable, symlinked or foreign-owned `gm_keys`, lets another local user act as the GM.
- Letting a player's `send_line` read sheets the resource refuses hands an agent every monster's block.
- Dropping the per-key limiter, the in-flight cap or the one-wait guard lets one player's agent tie up the host.
